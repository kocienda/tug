# The legacy sweep: a verified kill list, then the deletions

**Purpose:** The dash workflow has been rebuilt three times in a month — the join arc, the conductor, the interruption doctrine, the surface table — and each rebuild retired a design without always retiring its apparatus. The original note named a handful of suspects from memory. This brief is the read-only inventory it asked for first: every suspect checked against the tree as it stands after `verify-surfaces` joined, with the ones that turned out to be alive struck from the list and the ones nobody had named added to it. The plan that follows deletes; it does not investigate.

---

## Purpose {#purpose}

Two rules from the house style govern everything below. **A retired design is deleted, text and apparatus together — never marked "superseded by".** And **a retired *spelling* is kept as an alias** (`tuglaws/slash-commands.md`, "Retire a spelling"), because an unmatched `/verb` is submitted to claude as a prompt, which is worse than a rename. The sweep has to tell those two cases apart at every item: the first is a kill, the second is a keep.

The inventory was done by reading, not by recollection, and three of the original suspects did not survive it (see [F10]). That is the reason to inventory before cleaning: a sweep that trusts its memory deletes live code.

---

## Evidence {#evidence}

Each finding is one candidate, its verification, and its disposition — **kill**, **fix**, or **question**. A kill is certain; a fix is a live artifact carrying a stale claim; a question is a call the owner makes.

**[F01] `tugdeck/src/_archive/cards/conversation/` — kill.** Thirteen files (`conversation-card.tsx`, `session-cache.ts`, `ordering.ts`, …), last touched 2026-07-07, excluded from the build by `tsconfig.json` line 26 — and kept alive by exactly two tests that import through the exclusion: `src/__tests__/ordering.test.ts` and `src/__tests__/conversation-types.test.ts`. An archive directory whose only consumers are tests of the archive is a directory with no consumers. `session-cache.ts` is also the last IndexedDB code in the deck, which the memory file already marks as unwanted infrastructure. The directory and both tests go. **(verified)**

**[F02] `tugcode/probe-*.ts` (18 files) and `tugcode/probes/` (3 investigations, 61 tracked files, 772 KB) — kill, after one read.** The loose probes date from 2026-04-02 to 2026-05-28 and are referenced by nothing — not `package.json`, not the justfile, not `tugcode/CLAUDE.md`. The three `probes/` directories (`btw`, `goal-loop`, `wake-investigation`) hold July captures — raw `stdout`/`stderr`/`.meta.json` from real claude runs — plus a `FINDINGS.md` each. The findings are the only part with a reader; the plan checks each against `tuglaws/` (the side-question doctrine and the tool_progress note both exist there) and moves any conclusion not already recorded before deleting the directory. Captured transcripts in git are not fixtures: the fixtures live under `tugrust/crates/tugcast/tests/fixtures/stream-json-catalog/` and are regenerated by `just capture-capabilities`. **(verified)**

**[F03] Three CSS comments cite `roadmap/` paths that no longer resolve — fix.** `tug-atom-text-body.css:51` → `roadmap/dev-atoms.md#d08-tool-block-only`; `session-permission-dialog.css:16` → `roadmap/archive/dev-interactive-dialogs.md`; `tug-pane.css:139` → `roadmap/jul30-perf-brief.md#i1-sparkline-exception`. A comment pointing at a document that does not exist is a comment saying nothing; each is either re-pointed or reduced to what the code does. **(verified)**

**[F04] `tugplug/skills/dash/SKILL.md` §5 still carries the pre-conductor review fork — fix.** Lines 138–144: *"On Opus — the review runs inline … On anything else — stop … print `/tugplug:plan-review` … Never switch the user's model, in either direction, and never schedule a turn on their behalf."* Every sentence of that is contradicted by `tuglaws/conductor.md` and by the `plan-devise` conversion that landed in `215c57df2`: outside an arc the devise turn asks the conductor for the review, and a skill naming a model for its stage is not switching the user's. ## Decisions {#decisions}

**[B01] This brief is the inventory; the plan is the deletions.** No further investigation happens in the plan. Every step names files from the findings above, and a step that would need to decide whether something is dead is a step that does not belong in it — that decision was made here or is listed under Open Questions.

**[B02] Kills are whole.** A retired design goes with its tests, its fixtures, its registry lines, its tsconfig exclusion, and its CLAUDE.md roster entry, in one commit per finding. No `_archive/` move, no `// superseded` marker, no `deprecated` flag on a symbol that has no callers.

**[B03] Retired spellings stay; retired claims go.** `/join → /dash-join` remains an alias exactly as `slash-commands.md` prescribes. What changes is the sentence in `CLAUDE.md` that names the alias as the verb ([F05]). The same split applies to `dash/SKILL.md` ([F04]): the fork is deleted, and what replaces it is one paragraph pointing at `plan-devise` §5 rather than restating it — a second copy of the hand-off is how the first one drifted.

**[B04] Findings that are prose get sentences that are true today.** A CSS comment ([F03]) says what the code does, not where a plan once explained it; a decision record ([F08]) says what a deleted spike found, not where to find it. Comments that narrate history are the house's named anti-pattern, and the sweep does not replace one stale backstory with a fresher one.

**[B05] Probe findings are read before they are burned.** [F02]'s three `FINDINGS.md` files are compared against `tuglaws/` and the memory notes; a conclusion that lives nowhere else gets a home in the tuglaw it belongs to *first*, in one sentence, and the directory is deleted second. Captures are never kept as documentation.

**[B06] Landed paperwork is archived with its plan.** [F15]: a brief moves to `dash/archive/` when the plan it spawned does. `dash-notes.md` is folded — its four numbered items are now three landed briefs and one abandoned rename — and the note is archived once nothing in it is still open.

**[B07] Questions are asked in the devise round, and only the questions.** [F07], [F11], [F12], [F13], [F14] are five owner calls. The devise round raises each as one `AskUserQuestion` with *keep* / *delete* and the one-line consequence of each, and writes the answers into the plan as decided items. Nothing else in this brief needs the owner.

**[B08] The sweep leaves a method behind, not a habit.** Two mechanical checks from the inventory become permanent: a test that every `tuglaws/*.md` is listed in `INDEX.md` ([F06]), and a test that every relative document path in a source comment or tuglaw resolves ([F03], [F08]). Both are cheap greps; both would have caught their findings the day they became stale. Nothing broader — no `knip`, no unused-export sweep — is adopted here; the Rust side is already under `-D warnings`, and the deck's dead exports are a different brief if they are one at all.

## Open Questions {#open-questions}

- **[F07] — retire or cite `framework-architecture.md` and `list-surface-grammar.md`?** Each needs one read to say whether it states something no other document does.
- **[F11] — is the placement experiment still answering a question?** If not, it is a spike on the shipping card and goes with its three call sites and its `window.tugSessionPlacement` global.
- **[F12] — does a model ever join?** If the answer is the doctrine's *no*, `dash-join` is deleted, `dash-on`'s ending says *the shade is the door* like `dash-implement`'s does, and the CLAUDE.md roster drops it.
- **[F13] — keep the off-arc path in `plan-devise`?** Keep means a terminal claude can still devise a plan and get the chip; cut means `plan-devise` refuses to run without `TUG_DASH_ARC` and says so.
- **[F14] — is `diag/` in use?** The perf campaign it belongs to is open in the memory notes; if its scripts are how that campaign is driven, they stay and get a README line; if the campaign moved to `just` recipes, they go.

## Non-goals {#non-goals}

- **Renaming `tugutil`.** Skipped outright; the tools stay as they are.
- **Retiring `dash-on` or the quick-dash route.** The `/dash` orchestrator routes plan-less work there deliberately; whether the arc should absorb plan-less dashes is a workflow question, not a legacy one.
- **The `join_*` feeds, `/dash-bind`, and its error store.** Alive ([F10]); not touched.
- **Untracked directories.** `aside/` is not in git and is not the repository's to sweep.
- **A general dead-export hunt in tugdeck.** See [B08].

## Exit {#exit}

**A plan**, at `dash/legacy-sweep.md`. Its shape:

1. The certain kills: [F01] and [F02] ([B05] first), one commit each, with `bun test` and `cargo nextest` green after each.
2. The fixes: [F03], [F04], [F05], [F06], [F08], [F09], [F15], [F16], one commit per file family, each stating the true sentence rather than the historical one ([B04]).
3. The owner's five answers ([B07]), applied as kills or keeps.
4. The two permanent checks ([B08]) as `bun test` cases under `tests/app-test/scripts/` or a `tuglaws` test — wherever the existing doc-consistency tests live — each red against the tree before its finding was fixed.
5. The doctrine touch: one sentence in `tuglaws/dash-work-doctrine.md` naming the kill/alias split of [B03] as the rule for the next retirement.

The devise round asks the five questions and settles nothing else; the inventory is done.
