# Hardening the shell↔body bus after its audit

**Purpose:** The bus library that `a78e95fd2` landed (`briefs/shell-body-api-brief.md`) has the right shape and a careful implementation, and a cold read of it found four robustness defects in the core that a long life will meet, one law the arc wrote around rather than through, and a short list of housekeeping. This brief states each with its pinning test, so the core is sound before the bodies-migration thread resumes on it.

---

## Purpose {#purpose}

The user asked for a 360° audit of the shell↔body API implementation, "not just the plan in the abstract": code quality, coherence, technical choices, tuglaws conformance, and whether the architecture sets Tug up for the future; then "Do we need to make fixups? Or, can we move on from here?"

The audit's answer was: fixups first, then move on, and they are small. The user's call on the one decision the audit surfaced:

> As for 5, amend the law to admit a person-exit for a wait *on a person* (that's what it is) **and** make the close-decision timeout visible, not a dev-log line.

Everything else in the audit that is not a defect — the per-feature plumbing still in `lib/body-shell.ts`, the second copies in a body's stores, the uneven depth of `opaque` codecs — is recorded under Non-goals as the next layer, not this work.

---

## Evidence {#evidence}

All read from the tree at `a78e95fd2` on 2026-10-19; paths under `tugdeck/src/` unless said otherwise. The fast layer was run: 11,236 unit tests green, `tsc` clean, `bun run lint` red ([F10]).

**[F01] A throwing handler aborts the frame it rode in on, and the bus is now one listener.** `bus/page-bus.ts` `receive` calls the route for an envelope bare (`route(envelope)`, line 327), `receiveHello` the same; `connection.ts:1065` calls every frame callback bare (`for (const cb of cbs) cb(payload)`). A route fans out into a store's `notify()`, whose listeners are React subscribers and the shell's `watchCardStore` appliers, and into action and request handlers, which are app code. Before the arc each `onBus` listener was its own frame callback and failed alone; now one throw anywhere under the bus propagates out of the bus's single callback into the connection's dispatch of that frame. **(verified, read from the code)**

**[F02] A shell reload leaves a body's dialogs standing and loses the answer.** `bus/request.ts:155-156`: `onPeerHello` returns at once when the peer is the shell. Inbound requests a body is answering (`inbound`, keyed by `requestId`) are aborted only in `onCardGone` (lines 165-177), which fires only in the shell. So when the shell page reloads — a new epoch, a new `pageId` — a `session.ask` dialog or a close sheet the old shell raised stays up in the body, and when the person answers, `reply(delivered.from.pageId, …)` (line 99) addresses the dead page, which tugcast refuses as `bus_undeliverable`. `tuglaws/shell-and-bodies.md` §requests says the handler's signal aborts "when the asker's card goes away"; the shell is an asker with no card. **(verified, read from the code)**

**[F03] Replicas accept a `state` snapshot from any sender.** `bus/shared-store.ts` `receiveSnapshot` (lines 231-267) checks `isOwner()` and the codec and nothing about `delivered.from`: not that `from.role` is the owner's role, and in the shell not that `from.cardId === delivered.card` for a card-owned store. Actions (`routed-action.ts:54`), requests (`request.ts:114`) and proposals (`shared-store.ts:273`) all refuse a body speaking for another body; `state` is the one kind that does not, so a body could write a sibling's shell-owned replica, or another card's `card.facts` in the shell and reset its epoch. [L38] says the library drops body-to-body traffic. **(verified, read from the code)**

**[F04] Snapshot order on attach is module evaluation order.** A store's `onPeerHello` listener is registered when its declaration binds to the bus (`bindEveryPageBus`), in the order the declaration modules evaluate — the import order of `bus/registry.ts` and of `declarations/*.ts`. `declarations/card.ts:21-23` relies on it: "`card.painted` is declared after `card.facts`, so a body that attaches sends its facts first: the shell shows a body only once its facts have arrived." The shell's gate (`lib/body-shell.ts:425-428`, `notePaint`) marks a card `painted` when the host's half and `card.painted` have both arrived; it does not wait for `card.facts`. A reordered import would change when a body is shown, with nothing failing. **(verified, read from the code)**

**[F05] `{person}` horizons arm no deadline, and [L33] was not amended.** `bus/request.ts:25` admits `Horizon = { ms } | { person }`; line 225 arms a timer only for `ms`. `lib/close-decision.ts:34` takes `{ person: CLOSE_DECISION_EXIT }` when the body's guard says it asks, and `lib/pending-ask-store.ts:386` takes `{ person: SESSION_ASK_EXIT }` for every ask. `tuglaws/tuglaws.md` L33 reads "a deadline … a named terminal state … a user exit … Two of the three is not compliance", and `tuglaws/no-wait-without-a-horizon.md` has no occurrence of "person". `shell-and-bodies.md` §requests permits the person horizon; the law it cites does not. On the `{ms: 2000}` branch, `close-decision.ts:40-42` logs the timeout to the dev log and returns `"cancel"`: the named terminal state reaches nobody, the close silently does not happen. **(verified, read from the code)**

**[F06] `bindEveryPageBus` returns void, and the one caller outside the primitives leaks in tests.** `bus/page-bus.ts:465`: binders go onto a module-global array and are never removed. `lib/body-facts-store.ts:57-62`, in `BodyFactsStore`'s constructor, calls it and discards each `store.on(bound).subscribe(changed)` release. The production singleton lives as long as the module, so the product does not leak; `lib/__tests__/body-facts-store.test.ts:37` constructs one per test, and each stays in `binders` and subscribes to every page bus created after it. [L27]: no registration API may return void. **(verified)**

**[F07] Proposal bookkeeping has two inexact edges.** `shared-store.ts:92, 137, 281`: the owner's `acks` record gains one entry per replica `pageId` that ever proposed and is never pruned, and every snapshot carries the whole map — for the kinds-scoped `overview.draft` and `layout.selection`, every Overview or Cards body page ever created. `shared-store.ts:111, 147, 282, 290`: `publishedDuringProposal` is one flag per store binding, not per entry key, so a shell-owned card-scoped store whose `onProposal` handler publishes a *different* card's entry skips the republish that carries the proposer's ack, and the proposer keeps its optimistic value until that key happens to move. No current handler does this. **(verified, read from the code)**

**[F08] A held verb is dropped silently on `forgetCard`.** `page-bus.ts:337-351` `goneCard(cardId, true)` deletes the card's whole hold, actions included, with no log. `lib/body-shell.ts:1262` calls `forgetCard` on a `failed` body. A `jots.newJot` (⌘J), a `text.revealLine` or a `cards.spaceVerb` held for a body that then fails is gone with nothing said ([L31]). `lib/body-shell.ts:1358-1364`: the `onShellPointerUp` `setTimeout(…, 0)` is never cleared when the shell uninstalls. `lib/body-facts-store.ts:61` subscribes to `cardFacts`, `cardHolds`, `cardRestoreHold` and `cardKbfPaint` but not `cardContent`, so `contentOf` readers riding `bodyFactsStore.subscribe` are not told when a body's content height moves. **(verified, read from the code)**

**[F09] The legacy guard has gaps, and the new singleton is unlisted.** `bus/__tests__/no-legacy-bus.test.ts` forbids the five old kinds, eight identifiers, six module paths and nineteen setters, and requires exactly one export each of four allowed setters. It does not cover `"deck-call"`, `dispatchShellAction`, `SHELL_ACTIONS_FOR_CARDS`, `runShellActionForCard`, the three allowlists (`BODY_DECK_CALLS`, `SELECTION_CALLS`, `MINIATURE_RELAY_CALLS`), the queue names (`pendingIntents`, `pendingJotCaptures`, `standingAsks`, `pendingDecisions`, `sentContext`, `sentDeckFacts`), the deleted `jot-capture.ts` and `cycle-focus-forwarder.ts`, or `installKeyCardRoute` (`bus/command-route.ts:66`), the one module singleton the arc added. **(verified)**

**[F10] Lint is red on main, from before the arc.** `bun run lint` fails on three `no-restricted-imports` in `lib/body-shell.ts` (`components/tugways/modifier-latch`, `components/cards/cards-space-verb-request`, `components/overview/overview-composer-draft`; `lib` must not import from `components`) and one `no-unsafe-optional-chaining` at `lib/__tests__/body-handoff.test.ts:206`. All four are present at `e1716051f`. **(verified, run)**

**[F11] What the audit found sound, so this brief leaves it alone.** The three primitives and their registry test; one `held` queue per target with coalesced snapshots and snapshot-on-attach before the drain; the symmetric hello; `bus_undeliverable` read and logged; one parse per frame; the 239-line Rust envelope with its passthrough test; write-back with versions, epochs and acks; the deletion of eight modules and nineteen setters; the recorded 46/48 derived app-tests with `at0647` and `at0578` red for their own recorded causes. [L01], [L02] for React consumers, [L03], [L06], [L30], [L37] read clean. **(verified)**

## Decisions {#decisions}

**[B01] Every fixup lands with a test on `createTestBus()` that is red without it.** That is the law's own rule for a crossing (`shell-and-bodies.md` §tests), and it is what makes each fix a decision the suite remembers rather than a line someone may tidy away. The tests named below are the pinning tests; a fix without its test is not done.

**[B02] The page bus isolates every handler it calls.** `receive` wraps each route call, and `receiveHello` its listeners, so a throw is logged against the envelope's `kind:key` and `from` and the bus goes on; `notify()` in `shared-store.ts` isolates each listener the same way, so one React subscriber cannot starve the next. The connection's frame loop is left as it is: the bus is the one callback that fans out into app code, and the fence belongs where the fan-out is. **Pinning test:** a store subscriber on a body that throws; a second subscriber on the same store, and a routed action delivered in the same frame, both still run; the log carries one warning naming the store.

**[B03] A body aborts every request it is answering when the shell's epoch changes.** In `request.ts`, the body side watches the shell's hello: a hello from a `pageId` other than the one its inbound requests came from aborts each of them (`controller.abort()`), so the dialog a request raised comes down through the signal it already has. The reply path stays as it is; a reply has nothing to go to. The shell side needs nothing new: a reloaded shell holds no `outbound`, and `redeliver` requests are re-asked by their callers, as `pending-ask-store` already does on attach. `shell-and-bodies.md` §requests gains the sentence: the signal aborts when the asker's page goes away, card or shell. **Pinning test:** a shell asks `session.ask` of a body; the body's handler is pending; the shell page is replaced (`detach` of the shell on the test bus, a new shell page says hello); the handler's signal is aborted and no reply crosses.

**[B04] A replica takes `state` only from the store's owner.** `receiveSnapshot` refuses, with a warning, a snapshot whose `from.role` is not the owner's role, and in the shell one for a card-owned store whose `from.cardId` is not `delivered.card`. This closes the one kind the star did not cover, so [L38] is a guarantee for every kind. **Pinning tests:** two bodies on a test bus; one sends a `state` envelope for a shell-owned deck store to `"body"` and the other's replica does not move; a body sends `card.facts` naming a sibling card and the shell's `getFor(sibling)` does not move; the log carries the refusal.

**[B05] The shell's paint gate waits for `card.facts` itself, and attach order is declared rather than inherited.** `notePaint` marks a card `painted` only once the host's half, `card.painted` and `card.facts` have all arrived (`cardFacts.arrived(cardId)`), so the order snapshots arrive in no longer matters to what the user sees. And the implicit rule is made explicit at the declaration: a store may name `after: [store]`, which the page bus honours when it sends snapshots on attach; `card.painted` names `card.facts`, and `card.context` names `card.crossing` (the other order `card.ts:73` relies on). The registry test asserts every `after` names a registered store. **Pinning tests:** `registry.ts` imports reordered in a test harness so `card.painted` binds before `card.facts`; the shell does not show the body until the facts arrive, and the facts snapshot still precedes the painted snapshot on the wire.

**[B06] [L33] admits a person-exit for a wait on a person, and the close decision says so when it ends.** The user's call. `tuglaws/tuglaws.md` L33 and `tuglaws/no-wait-without-a-horizon.md` gain the clause: a wait whose other party is the person in front of the surface — a dialog, a sheet — is not a wait on a process; it names its user exit and its terminal states and arms no deadline, because the deadline would be on the person. A wait on a *process* keeps all three. `{person}` in `request.ts` is that clause, and its doc comment cites it. And the `{ms}` branch of `askCloseDecision` stops being a dev-log line: a body that does not answer its close decision in time surfaces as a named state in the card's pane — the pane flashes and a banner on the card says the card did not answer, with the close gesture as the way out — not a silent cancel. The dev-log entry stays beside it. **Pinning tests:** a unit test that the close decision's timeout dispatches the visible refusal for the card; an app-test, `at0574`-sized, under 20 s, that closes a body card whose guard is held silent and reads the banner in the shell (a `// card-dom: shell` read, since the banner is pane chrome).

**[B07] Registration returns its release, and the ack record is kept exact.** `bindEveryPageBus` returns an unbind that removes the binder and releases what it bound on every live bus; `BodyFactsStore` keeps the releases it takes and exposes `dispose()`, which its tests call. In `shared-store.ts`, `acks` entries are pruned when a replica page detaches or is forgotten (the owner hears `onCardGone` and, for a body replica, the shell's `onDetach`), and `publishedDuringProposal` is tracked per entry key, so a handler publishing another key still earns the proposer its ack. **Pinning tests:** a `BodyFactsStore` constructed and disposed leaves `binders` and the stores' listener counts where they were; a proposal whose handler publishes a different card's entry is still acknowledged to the proposer, and its optimistic view settles.

**[B08] A held verb that is dropped is logged, and the uninstall leaves no timer.** `forgetCard` logs each held action or request it drops, with the target and `kind:key`, so a lost ⌘J has a line someone can find ([L31]). The pointer-up `setTimeout` in `body-shell.ts` is kept in a handle the uninstall clears. `bodyFactsStore` subscribes to `cardContent` with the others. **Pinning tests:** a `jots.newJot` held for a card that is then forgotten appears in the log; `bodyFactsStore.subscribe` fires when a body sets `card.content`.

**[B09] The legacy guard covers what the audit named, and the allowed singletons are the whole list.** `no-legacy-bus.test.ts` adds the kind `deck-call`, the three shell-action symbols, the three allowlists, the six queue names, and `jot-capture.ts` and `cycle-focus-forwarder.ts` to the deleted modules; its allowed-setters list gains `installKeyCardRoute` as the fifth and names the rule — a setter is allowed only when it never crosses pages — so the list is the law's [L37] exception made checkable. The guard also matches a re-export (`export { x }`) and a setter outside `lib/`.

**[B10] Lint is green again, by moving the shared pieces into `lib`.** The three `lib`→`components` imports in `body-shell.ts` ([F10]) are resolved the way the rule's own help text says: the shared piece moves into `lib` and the component re-exports it. `modifier-latch`'s `heldModifiers`/`subscribeModifierLatch`, `cards-space-verb-request`'s slot and `overview-composer-draft`'s `holdOverviewDraftInShell` each go to a `lib` module. The test line at `body-handoff.test.ts:206` indexes without optional chaining. `just lint` is part of this work's verdict.

**[B11] The doc says what the code does.** `shell-and-bodies.md` corrects two sentences the audit found wider than the code: "nothing to mirror" becomes "a page's pre-existing stores are *fed* from replicas and never written back" (naming `createCardFactsMirror`, `cardsSelectionStore.take` and the body's own `cardSessionBindingStore` as that), and "a replica reads through `useSyncExternalStore`" becomes "a React reader does; an imperative reader subscribes and applies ([L22])". It records [B03]'s shell-epoch abort, [B05]'s `after`, and [B06]'s clause by reference to L33.

## Open Questions {#open-questions}

- **How the close-decision refusal is shown.** [B06] says a flash and a banner on the card's pane with the close gesture as the exit; whether the banner's words are the card's ("did not answer") or the shell's, and whether it auto-dismisses, is a surface call to make at the pane, not here. The arc reads `tug-pane-banner.tsx`'s existing refusals (the modal-hold refusal is the nearest) and matches them.

## Non-goals {#non-goals}

- **Dissolving the rest of `lib/body-shell.ts` into declarations.** 1413 lines and 28 concerns remain — `DEVTOOLS_KIND`/`SETTINGS_KIND` branches, ten per-card Maps `forget()` clears by hand, `watchCardStore`, the devtools log as a cursor stream. That is the next layer, its own brief, and not a defect in the library.
- **Replacing a body's pre-existing stores with replicas.** `createCardFactsMirror`, `cardsSelectionStore.take` and the body's own binding copy feed old stores from new replicas. Correct today; [B11] documents it; collapsing them is the layer above.
- **Deepening every `opaque` codec.** `deck.menu`'s `carried` and `arrangement.deck`'s two-field check are shallow by choice; a codec is deepened when a payload is refused for a reason it would have caught.
- **Fencing the connection's frame loop.** [B02] puts the fence at the bus, the one callback that fans out into app code; a try/catch around every feed's every callback would hide failures in paths that have none.
- **Resuming the bodies-migration reds before this lands.** The user's order: the API, then its fixups, then the thread.

The verdict is the unit suite, `bun run lint`, and the derived app-test selection for the touched files; no harness file changes, so the core tier is not advised.
