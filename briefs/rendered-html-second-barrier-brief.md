# Rendered HTML: a second barrier, a wider corpus, and a bounded render stage

**Purpose:** Model-generated markdown is now rendered to HTML in tugcast and written to the page's DOM through `innerHTML` with no sanitization on the page, under a Content-Security-Policy that permits inline script. The Rust sanitizer is sound in design, and it is one barrier where there used to be one, so the hole is not the sanitizer but the absence of depth around it: a thin, self-derived hostile corpus, DOMPurify internals hand-ported behind a caret range, and no real-WebKit hostile test. This brief adds the depth, and bounds the render stage's cost and wire.

Fixup to stage 5 of `briefs/main-thread-headroom-program-brief.md` (`briefs/tugcast-renders-brief.md`, landed as `dc6aaeb4f`).

---

## Purpose {#purpose}

The 2026-10-12 audit's security review of stage 5 concluded: "What I would not do yet is ship model-generated HTML through this sanitizer as the only barrier." The deck is a WKWebView with host bridges (clipboard, file IO through tugcast, shell). A surviving `on*` attribute or `<script>` is script execution with those bridges.

## Evidence {#evidence}

**[F01] The sanitizer is ammonia over html5ever, not a hand scanner.** `tugdeck/crates/tugmark/src/sanitize.rs:14`, `:136-192`: each block is parsed as an HTML5 fragment by html5ever, the tree is pruned against the allow-list, and html5ever's serializer emits canonical HTML. Foreign content (`svg`, `math`) and raw-text elements are dropped whole; comments are stripped; the attribute filter (`:331-345`) ports DOMPurify 3.3.3's `_isValidAttribute`, and its regexes were compared to the installed `purify.es.mjs:1124` and found identical. The hand-written `noscript` pre-pass (`:203-270`) diverges from the HTML5 tokenizer only in the safe direction. The hand scanner in `html_scan.rs` runs only over ammonia's canonical output. **(verified, read from the code and the installed DOMPurify)**

**[F02] The page writes tugcast's HTML without a second pass, under a permissive CSP.** `render-incremental.ts:209`, `:227` write `innerHTML` from the rendered record; `tugdeck/index.html:6` declares `script-src 'self' 'unsafe-inline' 'unsafe-eval'`. The stage brief's [B01] declined a page-side pass because the HTML "comes from tugcast over the loopback socket"; the trust level of the feed equals the page's own, so the residual is a tugmark or html5ever-versus-WebKit differential, and the CSP is what would let a survivor run. **(verified, read from the code)**

**[F03] The hostile corpus is thin and derived from the thing under test.** `tugdeck/crates/tugmark/corpus/hostile/` is five files, about 110 lines; `tugmark_drift.rs:35-38` carries two stream cases; there is no fuzzing. `corpus/golden.json` is generated by tugmark and checked against the page, so a rendering wrong on both sides is invisible, and nothing asserts the invariant that no element outside `ALLOWED_TAGS`, no attribute outside `ALLOWED_ATTR`, and no unsafe scheme survives. `at0730`, the only test through the real WKWebView, streams benign text. **(verified, read from the corpus and the tests)**

**[F04] DOMPurify internals are hand-ported behind a caret range.** `tugdeck/package.json:62` pins `dompurify: ^3.2.2` (3.3.3 installed); `sanitize.rs:286-345` ports its `SAFE_FOR_XML`, URI, `DATA_URI_TAGS`, `FORBID_CONTENTS` and input rules. A DOMPurify minor bump can diverge silently; the golden catches only what the corpus exercises. **(verified, read from the code)**

**[F05] A page-side pass over the new blocks is cheap by construction.** Emissions carry HTML only for new hashes (`render_stage.rs:148-158`), typically one block per delta. A DOMPurify pass over those entries is one small-block DOM parse per delta, against the whole-document parse plus per-block sanitize the stage removed (109.5 parses per second to 0 on the harness). Its cost has not been measured. **(inference from the mechanism; to be measured)**

**[F06] `id` and `class` are globally allowed on both sides.** `sanitize-allowlist.json:14`. Model HTML can set any `id` (the golden shows `id="body"`, `id="location"`, `id="cookie"` surviving on both sides) and any `class` (the page's `tugx-*` and `tug-syn-*` vocabularies). `SANITIZE_DOM` never guarded `window[id]` named access or `getElementById` collisions with page chrome. Pre-existing, not a regression. **(verified, read from the golden)**

**[F07] The render stage is one thread and the wire is whole-list.** `RenderJob::render` (`render_stage.rs:143-178`) renders every dirty message sequentially on one `spawn_blocking` thread per tick with one job in flight (`render_bridge.rs:383-390`, `:620`); the brief's "four sessions, four cores" is not what shipped. Each emission carries the message's whole block list (`tugproto/src/rendered.ts:48-49`), so JSON per tick scales with message length; the 105 KB/s reading is for short messages. The RENDERED broadcast capacity is 64 (`render_bridge.rs:230-232`); a lagging deck loses frames, resyncs, and receives the whole message's HTML again (`render_stage.rs:322-345`), which under sustained lag is positive feedback. In grep mode the page ships every remote unit's full text per debounced keystroke. **(verified, read from the code; measured only for the 4 KB to 128 KB render times)**

**[F08] Version skew degrades silently.** `RenderBatchFrame` and `RenderInput` carry no version. A new deck against an old tugcast leaves every live Message `pending` for 250 ms before parsing. The comment at `render_bridge.rs:495-497` says the text-hash check refuses a lagged render; a streaming record is drawn regardless (`rendered-record.ts:39`, `:50`). **(verified, read from the code)**

**[F09] The WASM package is not reproducible.** `tugdeck/crates/tugmark-wasm/pkg/tugmark_wasm_bg.wasm` differs from a local rebuild by one constant in core's data tables (offset 199799), a toolchain difference; there is no `rust-toolchain.toml`, and no step asserts the committed package is current with `tugmark`'s source. **(verified, byte compare)**

**[F10] Licensing is compliant.** Every tree-sitter grammar crate is MIT; ammonia's tree is MIT or Apache-2.0; `cssparser 0.38.0` and `dtoa-short 0.3.5` arrive MPL-2.0 and are listed with the MPL text in `THIRD_PARTY_NOTICES.md`. No GPL. **(verified, read from `Cargo.lock` and the notices)**

## Decisions {#decisions}

**[B01] The page keeps a second barrier on rendered HTML until the first has been fuzzed against WebKit.** `applyRendered` (or the `innerHTML` write) runs `getDOMPurify().sanitize` with the shared config over every new-hash HTML entry of an emission. This reverses the stage brief's [B01] and is written here as that reversal: the trust argument held for provenance and not for a parser differential. The cost is measured on the streaming arm before and after; if it is under one millisecond per delta on the whale arm it stands. It comes off only when [B03]'s fuzz and the real-WebKit test have come back clean, by a decision recorded in this brief.

**[B02] The CSP stops permitting inline script.** `script-src` drops `'unsafe-inline'`; `'unsafe-eval'` is read for who needs it (the eval door, WASM instantiation) and kept only where a nonce or a hash cannot serve. This holds whether or not [B01] stays, because it is the clause that turns a sanitizer miss into a rendered string rather than an executed one.

**[B03] The corpus gains an invariant, DOMPurify's fixtures, a fuzz run and a real-WebKit hostile test.** An invariant test parses every golden block and asserts element in `ALLOWED_TAGS`, attribute in `ALLOWED_ATTR`, scheme in the safe set, no `data-` or `aria-`; DOMPurify's `test/fixtures/expect.mjs` payloads are imported as hostile cases on both sides; a differential fuzz (random markdown and HTML fragments through tugmark, reparsed, invariant asserted) runs as an on-demand recipe and once in CI at a fixed seed; and one app-test streams a hostile stub turn through the real pipeline into the real WKWebView and asserts the invariant on the live DOM.

**[B04] DOMPurify is pinned exactly and the port is held to it by a test.** `package.json` pins the version the port was made against, and a test compares the ported regexes and lists to the installed `purify.es.mjs` by string, so a bump fails the suite rather than diverging.

**[B05] `id` and `class` are restricted on both sides.** `id` is admitted only in the footnote shape with a prefix the page owns, with `href="#…"` rewritten to match; `class` only in pulldown-cmark's vocabulary (`language-*`, `footnote-*`). The `tugx-*` and `tug-syn-*` classes are produced post-sanitize only. One allow-list, as today.

**[B06] The render stage is parallel across messages and bounded per tick.** Dirty messages render on `rayon` or per-item `spawn_blocking`, and a tick's work is capped with the remainder carried, so latency is bounded by the slowest message rather than the sum. Emissions carry the block list as a diff from the first changed index, as HTML already is. The RENDERED broadcast capacity rises for the uncompressed feed and resync carries a per-message backoff. Grep mode sends the page's known text hashes so tugcast omits texts the page holds.

**[B07] The feed carries a version and a lagged streaming record is refused.** `RenderBatchFrame` and `RenderInput` gain a `v` field; an engine that learns tugcast cannot render skips `pending`. A streaming record whose `textLength` exceeds the Message's current text is refused, which catches the lagged-tap case the comment at `render_bridge.rs:495-497` claims is already caught; the comment is corrected.

**[B08] The toolchain is pinned and the package is checked.** `rust-toolchain.toml` at both crate roots, and a lint step that rebuilds the WASM package and fails on `git diff --exit-code tugdeck/crates/*/pkg`.

**[B09] The render tracker is its own unit.** The render-tracking state machine in `session-engine.ts` (`RenderTrack`, `trackRenders`, `acceptRender`, `finalizeRender`, `isCurrent`, the finishers) is extracted to a `RenderTracker` with direct unit tests; `finisher` is typed as the timer source's handle. `RenderStage::resync`'s ignored return, `text.rs`'s dead tag names, and the per-block lowercase allocation in `noscript_as_element` are cleaned.

## Open Questions {#open-questions}

- **Does anything on the page need `'unsafe-eval'` besides the eval door and WASM?** Read from the code; the arc's first step. If only those two, a nonce for the door and `'wasm-unsafe-eval'` serve.
- **What does the second barrier cost on the whale arm?** Measured by the streaming arm. The expectation is well under a millisecond per delta; a reading above that is a finding, not a reason to drop the barrier.
- **Is the fuzz oracle jsdom or WebKit?** jsdom is what runs under `bun test`; the real-WebKit assertion is the app-test. Both run; the app-test is the one that counts.

---

## Non-goals {#non-goals}

- **Replacing ammonia or html5ever.** The design is right; the depth around it is what is missing.
- **Rendering restored rows in tugcast.** The stage brief left it for a reading of restore paints; still open, not this brief.
- **Compressing the feed.** Over loopback at these sizes the block-list diff is the saving that matters.

---

## Exit {#exit}

**An arc.** The shape: the CSP ([B02]) and the second barrier ([B01]) first, with the cost reading, because they are the clauses that make a miss harmless; then the corpus, the fixtures, the invariant and the pin ([B03], [B04]); then `id`/`class` ([B05]); then the render stage's parallelism, the block-list diff and the wire bounds ([B06], [B07]); the toolchain pin and the tracker extraction ([B08], [B09]) last. The real-WebKit hostile app-test is the arc's gate.
