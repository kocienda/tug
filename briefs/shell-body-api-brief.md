# The shell↔body API

**Purpose:** The shell page and its body pages (one WKWebView per card) exchange state and verbs through a bus that was designed for five message kinds, and the bodies migration has since grown twenty-odd per-feature wires around it — relays, mirrors, forwarder singletons, opaque fields, sub-protocols inside `dispatch`. Every new body↔shell defect is fixed by adding another. This brief states what the wires actually carry, and decides the one mechanism they should all become.

---

## Purpose {#purpose}

The user's words, 2026-10-18, after a day of fixing the corpus against bodies:

> It seems to me that for quite some time here in these attempts to get all the tests working, that we are struggling with poor communications and APIs to connect bodies with the shell. … Are you just trying to go ad-hoc and add little crappy bits of API for every little thing, rather than stepping back and thinking about the kind of API we need to make all of these bug fixes easier and more robust to implement.

And the mandate:

> I want an *excellent* API that will stand the test of time. We *know* what this new model is, and, by now, we should have *abundant* experience to know what a good shape would look like. … Once we implement the better API, we'll come back and redo/remove/replace the ill-advised accretion that has built up.

The model is settled and is not reopened here: one shell page holding chrome, arrangement and the policy of focus; one body page per card holding the card's content; the host moving and focusing the bodies (`briefs/per-card-web-views-program-brief.md` [B01]–[B04], `briefs/every-card-a-body-brief.md` [B01], [B09]). The three channels stand: host ↔ page over `WKScriptMessage`, shell ↔ body over the tugcast `DECK_BUS`, host → shell over the control socket. What is wrong is the *shape of what rides the second channel*, and the seams inside each page where card code reaches for a deck that is not there.

The recurring defect of the migration ([B28]–[B30] of `briefs/app-test-bodies-migration-brief.md`) has one shape: a store the shell and a body both hold copies of, with nothing carrying it between them, or carrying it one way only. The sixteen product fixes of the last round were sixteen instances of that shape, each closed with its own wire.

## Evidence {#evidence}

Everything below was read out of the tree at `211be41cc` on 2026-10-18 (an exhaustive inventory by file and line, condensed here). Paths are under `tugdeck/src/` unless said otherwise.

**[F01] The bus has five kinds, closed in Rust, and nine opaque escape hatches.** `tugproto/src/bus.ts` and `tugrust/crates/tugcast-core/src/bus.rs` declare `card-facts`, `card-advice` (body → shell), `card-command`, `deck-facts`, `card-context` (shell → body), held equal by `tugproto/src/__tests__/fixtures/bus-parity.json`. The Rust structs are closed — a `kind` or variant not named fails to parse, and `bus.rs`'s own header says so — but tugcast never reads a payload: it stamps `from` and routes. Growth has gone around the closure: `CardFacts.masthead/identity/titleBar`, `DeckFacts.menu/frontmostProject`, `CardContext.arrangement/followed/appInfo/crossing` are all `Option<serde_json::Value>`, and `CardFacts.telemetry` is `BTreeMap<String, f64>`. The whole `BodyArrangement` (`lib/body-arrangement.ts:51`, twelve fields) travels inside `arrangement`. So the closure protects nothing a page relies on and still costs a Rust change and a bundle rebuild for any field that is not already opaque — which is what blocks `at0387`, `at0645` and `at0480` today ([B30]). **(verified)**

**[F02] A field added without the Rust change is dropped silently.** The structs have no `deny_unknown_fields`, and tugcast re-serializes every frame through them (`router.rs`, `route_bus`), so a new top-level key a page sends arrives nowhere, with no error on either side. Fields inside an opaque `Value` survive. The `telemetry` bag's documented contents are `canInterrupt` and `compacted`; it actually carries `restoreHold`, `restoreTurnsLoaded`, `restoreTurnsTarget`, `kbfPaint` and the content-height keys of `lib/rail-fit.ts:189` — the bag is where new facts go to avoid the rebuild. `lib/yielded-kbf-paint.ts:15` says the body sends "`kbf-paint` advice"; no such advice exists, the value rides `telemetry.kbfPaint`. **(verified, read from the code)**

**[F03] Twenty-two module-singleton setters bridge the pages, each one function wide.** Every one exists because card code calls a module function that reaches the deck in the shell and nothing in a body, and a body needs the call to cross the bus: `setShellActionForwarder` (`action-registry.ts:119`), `setUnhandledCommandFallback`, `setKeyCardForwarder`, `setCardContentForwarder` (`command-dispatch.ts:96, 65, 113`), `setUnhandledTargetHook` (`responder-chain.ts:490`), `setBodyGestureCard` (`gesture-interpreter.ts:152`), `setFocusWalkEdge`, `setCycleFocusForwarder`, `setKeyboardYield`, `setYieldedKbfPaintSource`, `setShellSurfaceHost`, `setLogoutForwarder`, `setBodyLineRevealer`, `setJotCaptureForwarder`, `setAskForwarder`, `setBodyIntentForwarder`, `setBodyReloader`, `setFirstBodyBagSeed`, `installOverviewDraftShellHolder`, `setCardsShrinkForwarder`, `registerSettingsRevealConsumer`, `registerMiniatureDropHost`, plus `setLayoutCursorCard` written from three places. Half are installed by `body/body-main.ts`, half by `lib/body-shell.ts`, and each has its own consumer in card code. **(verified)**

**[F04] Six relay modules, one store each.** `lib/cards-selection-mirror.ts` (123 lines: the Cards selection and cursor, body → shell as whole-snapshot `deck-call`s, shell → body inside `arrangement.selection`), `lib/miniature-relay.ts` (303: gauges shell → body as `dispatch {id: "miniature-relay", relay: "gauges"}`, drop-zone verbs body → shell as `deck-call`, zone answers back with a hand-rolled `requestId`), `lib/shell-keyboard-hold.ts` (51), `lib/yielded-kbf-paint.ts` (39), `lib/body-binding-mirror.ts` (53: when the shell lets go of its copy of a body card's session binding), `components/overview/overview-composer-draft.ts` (185: the Overview draft held by the shell across the rail, body → shell through a `hold-overview-draft` shell action, shell → next body as a first-bag seed). `lib/body-facts-store.ts` (153) is the shell's generic map of each body's last facts, and is the one of these that has the right shape. **(verified)**

**[F05] Three sub-protocols live inside two bus kinds.** `deck-call` advice carries three method allowlists — `BODY_DECK_CALLS` (`body-arrangement.ts:100`, eight deck methods), `SELECTION_CALLS` (`cards-selection-mirror.ts:40`), `MINIATURE_RELAY_CALLS` (`miniature-relay.ts:50`) — and `dispatch` carries ordinary command ids beside `miniature-relay`, `RUN_CARD_COMMAND` and `CARDS_SHRINK_COMMAND`, which `body-main.ts:850-856` special-cases by id. Six declared `card-command` kinds (`find`, `focus-prompt`, `interrupt`, `turn-previous`, `turn-next`, `chord`) are sent from nowhere. **(verified)**

**[F06] A message to a body not yet heard is lost, and five places queue around it by hand.** tugcast refuses a target no live page answers with a CONTROL `bus_undeliverable`; no page reads that error (`tugproto/src/bus.ts:10` is the only mention outside Rust). tugcast keeps a `departed_cards` window (`pages.rs`, `card_live_or_recent`) with no production caller. So `body-shell.ts` keeps a `heard` set and sends nothing to a card until its first `card-facts`, and queues per feature until then: `pendingIntents`, `pendingJotCaptures`, `standingAsks`, `pendingDecisions`, and `lib/jot-capture.ts`'s own queue; `at0656`-class defects ("a ⌘W just after ⌘N did nothing") are this window. Dedupe is by JSON string (`sentContext`, `sentDeckFacts`, `sentActivities`). **(verified)**

**[F07] Three request/reply exchanges are each hand-rolled.** `ask` → `ask-response {requestId, choice}`; `close-decision` command → `close-decision` advice with a 2 s deadline in the shell (`body-shell.ts`, the close-guard proxy); the miniature zones' `requestId` inside `dispatch`. No correlation, timeout or horizon is shared between them. **(verified)**

**[F08] Ownership is split for the stores that failed.** Selection and cursor are written in the Cards body (`cards-card.tsx:1448`) and the shell (`cards-selection-store.ts`); the Overview draft lives in a body that a hidden rail destroys; the session binding is written in both pages (`body-binding-mirror.ts` exists to decide which copy wins); the layout cursor is set from three files. Each defect in the [B30] catalogue is a case of two copies with no owner. **(verified)**

**[F09] The bridge is a 591-line stand-in with fifty inert methods.** `body/body-deck-bridge.ts` implements `IDeckManagerStore` for one card from a synthesized one-pane `DeckState`, forwards five verbs as advice, and answers about fifty layout, rail, column and space methods by logging `inert` once each — counted by `shellReads()`. `body-shell.ts` is 1499 lines with twenty-four distinct concerns; `body-main.ts` is 1019 with twenty-one. Neither is a layer; both are the places every wire ends up. **(verified)**

**[F10] `onBus` parses every frame once per listener.** `lib/deck-bus.ts:34` registers a frame listener per `onBus` call and each `JSON.parse`s the whole payload before checking `kind`; the shell has about a dozen and each body several. A frame is parsed N times. **(verified)**

**[F11] Each relay is tested against its own fake.** `miniature-relay.test.ts`, `cards-selection-mirror.test.ts`, `body-binding-mirror.test.ts` and the rest each take a `send` callback and drive it by hand; there is no in-memory bus a test can stand a shell and two bodies on. **(verified, read from the tests)**

**[F12] The law was decided and never written.** `every-card-a-body-brief.md` [B09] names `tuglaws/shell-and-bodies.md` — the three channels and what each carries, what a test may assume about documents. `tuglaws/` has no such file. **(verified)**

**[F13] The round's one regression that is not this shape.** The right-click menus that no longer open in a body (`at0307`, `at0346`, `at0574`, `at0599`, likely `at0560`/`at0568`) are host event routing: a probe on `at0599` saw the shell's `pointerdown` land on card A's own placeholder (`DIV[A] > .tug-pane-content > …`) at a point inside A's visible body frame with no `pointerClaim` standing, and the shell raised "No Actions". That is the host's hit-test, not a missing wire, and it is worked on its own. **(verified, probe)**

## Decisions {#decisions}

**[B01] Everything that crosses the bus is one of three things: a shared store, a routed action, or a request.** Reading [F01]–[F09] together, every wire carries either *state one page owns and another reads* (facts, context, arrangement, selection, draft, hold, guard, reservation, surface, paint word, menu facts), *a verb one page asks another to run* (dispatch, content action, focus enter, new jot, reveal, intent, deck calls, shell actions), or *a verb that answers* (ask, close decision, zones). The API has exactly those three primitives and no fourth; a need that fits none is a design question, not a new kind. This rules out adding a bus kind, an advice variant, a `dispatch` id with its own sub-grammar, or a module singleton, for any future shell↔body need.

**[B02] A shared store has one owner page and any number of replicas, and is declared once.** `defineSharedStore<T>({ key, owner, scope, codec })`: `owner` is `"shell"` or `"card"`; `scope` is `deck` (one value, to every body), `card` (one value per card, to that card's body or from it), or `kinds` (to bodies of named component kinds). The owner page writes with `set`/`update`; a replica reads with `useSyncExternalStore(store.subscribe, store.getSnapshot)` ([L02]) and may not write. Every replication the inventory names becomes a declaration: deck facts, card context, arrangement (split by change rate — the deck, the spaces, the bindings, the titles and identities, the activities — so a title change does not resend the deck), the Cards selection and cursor, the Overview draft, the binding, each body's facts (title, masthead, activity, identity, title bar), its hold states (fold guard, close advice, close guard, modal hold, capture armed), its reservations (sheet, opening bid), its surface, the KBF paint word, the restore hold, the content height, the menu facts and frontmost project. The body-facts map the shell keeps (`body-facts-store.ts`) is what a `card`-scoped store is for every card, generically.

**[B03] A shell-owned store a body edits gets a write-back, never a second copy.** The failed stores ([F08]) are shell-lifetime state edited from a body: selection, cursor, flow offset, the Overview draft, the layout cursor. Each is declared `owner: "shell"` with `propose(patch)` on the replica, which sends a routed action the owner applies and republishes. The body never holds an authoritative copy, so there is nothing to mirror and nothing to reconcile. The rule for choosing an owner is the state's lifetime: state that must outlive a body (a hidden rail's draft) is the shell's; state that dies with the card's content (a card's masthead) is the card's.

**[B04] A routed action is a command with a declared owner, dispatched through the one front door.** `dispatchCommand` already exists as the front door ([P04], `command-dispatch.ts`). Every verb that crosses pages becomes a registry row with `owner: "shell" | "key-body" | "card:<id>" | "here"`, and `dispatchCommand` routes by owner — in-page when the owner is this page, over the bus otherwise, with no caller knowing which. This subsumes `dispatchShellAction` and `SHELL_ACTIONS_FOR_CARDS`, the unhandled-command fallback, the key-card and content forwarders, the cycle-focus, jot, line-reveal, settings-reveal, logout and Cards-shrink forwarders, `run-card-command`, every `deck-call` allowlist and the miniature verbs. The `deck-call` advice goes: a deck method a body may call is a routed action owned by the shell, with the allowlist as the registry's own rows. "Menu-only verbs with no command row" ([ACTIONS_OUTSIDE_THE_TABLE]) get rows; the table is the place verbs are named.

**[B05] A request is a routed action that answers, with a horizon.** `request(action, payload): Promise<Reply>` carries a correlation id the bus library mints and a timeout the caller names (`tuglaws/no-wait-without-a-horizon.md`); the answer rides one `reply` kind. `ask`/`ask-response`, the close decision and its 2 s deadline, and the zones exchange are the three callers on day one. The three hand-rolled correlations go.

**[B06] The bus library owns liveness, so no feature queues by hand.** The shell knows when a body attaches (its `hello` after `page_bind`) and detaches (`bodyDestroy`, departure). The library holds, per target, what was sent before attach — a store's latest snapshot, a routed action, a request — and delivers it on attach, in order; `heard`, `pendingIntents`, `pendingJotCaptures`, `standingAsks`, `pendingDecisions` and `jot-capture.ts`'s queue are replaced by it. On attach the owner page sends every store the new replica is scoped to, as a snapshot, before anything else, so a body never reads a store that has not arrived. tugcast's `bus_undeliverable` becomes a reading the library logs against the target it knew was down, and `card_live_or_recent` is either used by this or deleted. Dedupe is by a per-store version number, not by JSON string.

**[B07] tugcast routes an envelope and reads none of it.** `bus.rs` keeps the envelope — `to`, `from`, `kind` (`state`, `action`, `request`, `reply`, `hello`), `key`/`id`, `version`/`requestId`, and an opaque `payload: Value` — and the five typed kinds with their closed structs and enums are retired. The parity fixture shrinks to the envelope. Each store's and action's payload type lives once, in TypeScript, next to its declaration, and is validated at the receiving page by that declaration's codec, so a malformed payload is refused where it can be seen, not stripped in transit ([F02]). A new store or verb is then a TypeScript change with no rebuild, which is what the `bus.rs` blockers of [B30] (`at0387`, `at0645`, `at0480`) need and what the opaque fields were reaching for anyway. The one Rust fact tugcast keeps is addressing; direction is the declaration's, as the Rust header already concedes.

**[B08] Topology is a star: bodies speak to the shell, never to each other.** A body that needs another card's facts reads a shell-owned store that projects them (the arrangement's titles and activities already are this). Body-to-body addressing stays out of the library's surface, so the shell remains the one authority on what a card knows about the deck ([B01] of the program brief), and a body's failure cannot reach a sibling.

**[B09] One page module answers "which page am I".** `page.role`, `page.cardId`, `page.isShell` replace `setBodyGestureCard`, the body half of `setKeyboardYield`, `setFocusWalkEdge`'s two installers and the `bodyCardFilter` checks: a module that behaves differently in a body reads the page, not a singleton someone remembered to set. The shell-only gestures that hold the keyboard (`shell-keyboard-hold.ts`) stay shell-local — they are not a crossing — and feed the one keyboard-owner store ([B02]) the shell owns and the host reads.

**[B10] One in-memory bus for every test.** `createTestBus()` stands up a shell page and N body pages on a fake transport with the real library on both ends — attach, detach, snapshot-on-join, queueing, request timeouts — so a store or action is tested as an exchange between pages, not against a `send` callback. The relay tests ([F11]) are rewritten onto it as the relays are retired. Two conformance tests ride it: every shared store and routed action is declared in one registry (an enumeration test, the shape of `body-stores.test.ts`), and every declared store round-trips its codec.

**[B11] The law is written with the API.** `tuglaws/shell-and-bodies.md` ([F12]) is written in the same arc, and says: the three channels; the three primitives and the rule that nothing else crosses the bus; owner-by-lifetime and write-back; star topology; snapshot-on-attach; what a test may assume about documents. `tuglaws.md` gains the law lines; `design-decisions.md` records the retirement of the typed bus vocabulary as a reversal of the program brief's [B04] phrase "a new addressed bus … (title and masthead facts, …)" — the *addressing* stands, the *vocabulary* moves to declarations.

**[B12] Build beside, move onto, then delete; the open reds are worked on the new shape.** The primitives, the test bus, the law and the Rust envelope land first with nothing moved. Then each existing wire moves in order of blast radius — deck facts and card context, then card facts and the hold states, then arrangement and selection, then the relays, then the verbs — each move deleting the wire it replaces and re-pointing its tests to the test bus. `body-shell.ts`, `body-main.ts` and the bridge shrink to the declarations and the host plumbing. The twenty-seven pre-existing reds of [B30] whose cause is a per-page store are fixed by declaring the store, not by patching the old wire; the nine regressions and `at0600`'s budget are worked as the migration brief says. Nothing in `components/` learns it is in a body ([B05] of the body-view brief, kept): the primitives satisfy the same contexts.

## Open Questions {#open-questions}

- **Snapshots or patches for the large stores.** [B02] says a store publishes a snapshot with a version; the arrangement, split by change rate, is a few kilobytes per change, which is fine. If a store turns out to churn (the Cards list of every session's facts, say), the library grows a patch form for that store alone. The threshold is a measurement to take on the user's deck once the stores exist, not a call to make here.
- **Where the host channel's repeats go.** `postToHost` has its own dozen names and `window.__tugBridge` its own callbacks ([F03]'s pattern, one channel over). Whether the host ↔ page channel wants the same three primitives is a later brief; this one leaves it as it is so the Swift side moves only for the envelope ([B07]).

## Non-goals {#non-goals}

- **Reopening the model.** One shell, one body per card, the host as mover, the shell as authority on arrangement and focus — settled by the program brief and read on the user's deck. This brief changes how the pages talk, not who decides what.
- **A generic RPC or a second deck store in the body.** The bridge's fifty inert methods ([F09]) are the shape of pretending a body holds a deck. The answer is fewer methods with declared owners, not a reflection layer that forwards any call.
- **Body-to-body messages.** Rejected by [B08]; a sibling's facts come through the shell's projection.
- **Keeping the typed Rust vocabulary "for safety".** It protects nothing a page relies on ([F01]), silently drops what it does not know ([F02]), and costs a rebuild per field. Validation moves to the receiving page, where a refusal is visible.
- **Patching the thirty-six reds on the old wires first.** The user's call: the API first, then the accretion is redone on it. A fix landed on a relay that is about to be deleted is work done twice.
- **Fixing the right-click regression here.** It is host hit-testing ([F13]) and is worked in the migration brief's own thread.

## Exit {#exit}

**An arc.** Its first steps, in the order they must land: the three primitives and the page module in a new `tugdeck/src/bus/` with the in-memory test bus and the two conformance tests ([B01]–[B06], [B09], [B10]); the Rust envelope and the shrunken parity fixture ([B07]) with `just app-test-build`; the law ([B11]). Then the moves of [B12], each one deleting what it replaces: deck facts and card context first, because every body reads them and they prove snapshot-on-attach; card facts and the hold states next; arrangement and selection, retiring `cards-selection-mirror.ts` and the `deck-call` allowlists; the miniature relay, the binding mirror, the Overview draft holder and the KBF paint source; then the verbs, retiring the forwarder singletons one registry row at a time. The core tier runs once at the first move (the harness surface changes) and the [B30] reds are re-run as their stores are declared. The migration brief's [B30] thread resumes on the new shape when the last singleton is gone.
