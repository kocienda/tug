# Content visibility: the audit, and the one rule it leaves behind

**Purpose:** The cold read that `workspaces-content-visibility-brief.md` `[B01]` called for, run over every mechanism that decides whether content is visible. It finds that the blank card is not an animation defect but the first bite of a transition class the workspaces work created and nobody declared — a remount into a subtree with no boxes — and it names the three mechanisms that fail toward invisible, the two that fail toward stale, and the six that already do it right.

---

## Purpose {#purpose}

The predecessor brief pinned one defect and asked for the reckoning it earns:

> We have experienced some very bad regressions lately in the area of content, card, shade, and sheet visibility. It feels like the "fixes" you've made are band-aids at best and *horrid hacks* at worst. [...] I want a full reckoning and complete cleanup and refactoring of this code to get us back on a stable footing, with a full tuglaws audit as well.

That brief's `[B01]` set the standard: *the deliverable is a 360° read of every landing and every mechanism, cold, against `tuglaws/tuglaws.md` and `tuglaws/design-decisions.md`, with the code that makes content visible reduced to rules a reader can hold.* This document is that read. It supersedes nothing in the predecessor — `[F01]`–`[F08]` there stand as measured — and it answers the two questions that brief left open while adding the root cause neither of them had reached.

The read's organising question turned out not to be "which mechanism is wrong." It is: **when this mechanism cannot answer, which way does it fail?** Every sound mechanism in this area answers *toward visible*. Every defective one answers toward invisible or toward stale. That single test sorts all eleven cleanly, and it is the law this brief exists to write down.

---

## Evidence {#evidence}

### The root cause

**[F01] Every cross-workspace card move is a full unmount and remount of the card's entire React subtree, by construction** — `DeckCanvas` renders one wrapper per mounted workspace as `<div key={layer.spaceId} className="tug-space-layer">` (`tugdeck/src/components/chrome/deck-canvas.tsx:5544`). A pane that moves workspaces changes React parent, and a changed parent is a remount whatever the keys below it say — `[L26]`'s three identity inputs cannot save an element whose *ancestor* differs. So `TugPane` → `CardHost` → `CardPortal` → the card's content component all come down on one side and are built fresh on the other. **(verified, read out of the code)**

**[F02] The remount is declared, and `moveCardToSpace` handles it correctly for user data** — its docstring states the consequence outright: *"Whichever case it is, the moving cards' panes are rebuilt, because a pane leaves one workspace's layer and is stood up in another's. [...] So every case captures first (`[L23]`)"* — and it calls `invokeSaveCallback(id, "space-switch")` unconditionally for every moving card before any store write, so the `[A9]` bag replays on the far side (`tugdeck/src/deck-manager.ts:1616–1675`). The move is not a hidden teardown; it is a known one with the `[L23]` cross-session protocol correctly applied. **(verified, read out of the code)**

**[F03] What the `[A9]` bag does not carry is derived appearance, and that is the whole defect class** — a `CardStateBag` carries scroll, DOM selection, focus, form-control values and content. It does not carry the state a mount-time effect computes for itself: an entrance's end state, a published CSS metric, a measured cap. Those are re-derived at mount, and on the destination side the mount happens inside `.tug-space-layer { display: none }` (`space-layer.css:28`), where every measurement reads zero and every animation finishes on an element with no box. So the workspaces work introduced a **third transition class** — *remount into a subtree with no boxes* — and `[L23]` names only two (in-session minimal mutation; cross-session capture-and-replay). Every mount-time one-shot in card content became a latent defect the day `b2174629f` landed; the blank card is the first one to bite, and `[F03]` of the predecessor brief (the composer's 14px line box) and `[F04]` (78 tool blocks at `0px`) are the same event seen at two other altitudes. **(verified: the mechanism read out of the code; the symptoms measured live in the predecessor brief)**

**[F04] The class is bounded, and small** — a census of `components/` for mount-once effects (`useEffect`/`useLayoutEffect` with an empty dependency array) turned up **six** that write to the DOM and **four** that measure it, excluding tests and spikes. Of those, `tug-transcript-entry.tsx:518` already registers a `ResizeObserver` rather than reading a rect, `jots-card.tsx:522` refuses safely on a zero height (`if (target <= 0) return`), `tug-editor-context-menu.tsx` and `gallery-atom.tsx` are not card content that can mount hidden, and `tug-list-view.tsx` and `pdf-view.tsx` warrant a look but were not implicated. The genuinely broken set is **one**: `session-card.tsx:2744`. The refactor this brief calls for is therefore a small, enumerable edit, not a sweep. **(verified, by script over the tree)**

### The mechanisms that fail toward invisible — the hacks

**[F05] `SessionCardBody`'s first-mount fade writes a hide by hand and delegates the lift to a call the codebase documents as throwing** — `session-card.tsx:2762` sets `el.style.opacity = "0"` synchronously, opens a `TugAnimator` group, and relies on the group's `commitStyles()` to land the end value. `tug-animator.ts:355–360` wraps that call in `try { wapiAnim.commitStyles(); } catch { /* target detached; nothing to commit */ }` and then cancels the animation. `commitStyles()` throws `InvalidStateError` for an element that is not being rendered, which is exactly what a card mounted under `display: none` is. The effect's own comment asserts the opposite — *"Cleared on animation completion via tug-animator's commitStyles() path"* — and the comment is what made this invisible to review. Nothing re-runs the fade; a later workspace switch changes the layer's `display` and touches no inline style. The card is blank with no way back. This confirms the predecessor's `[F02]` and adds why it is not a one-line patch: the *caller* never writes its own end state. **(verified: the writer read out of the code; the resulting state measured live in the predecessor brief; clearing the inline opacity restored the user's card)**

**[F06] `CardHost`'s pre-restore opacity mask is `[L31]`'s third named violation shape, with no deadline** — `card-host.tsx:802` writes `hostContentElRef.current.style.opacity = "0"`, and the only code that lifts it lives inside `callbacks.onContentReady` (`card-host.tsx:783`). That callback fires from a no-deps `useLayoutEffect` in `use-card-state-preservation.tsx:376`, gated on `restorePendingRef.current`, which `card-host.tsx:853` sets immediately before calling `callbacks.onRestore(...)`. So the mask lifts if and only if the child component commits again after `onRestore`. A content factory whose restore is a pure DOM write with no state change never commits, and one that throws inside `onRestore` never gets there — in both cases the mask stands and the card is blank. `[L31]` names this shape exactly: *"a callback parked on an event that may never fire — the gesture is accepted, deferred to a beat that is not guaranteed to arrive, and lost with no error, no timeout, and no trace. Deferred work carries a deadline."* There is no deadline here. **(verified that the code has this shape and no deadline; that a real content factory takes the stranding path is inference, not a reproduction)**

**[F07] Both hacks are the same shape, and it is the shape `[B02]` of the predecessor brief predicted** — *a hand-written inline opacity that a separate party is expected to undo*. In `[F05]` the separate party is WAAPI's `commitStyles()`; in `[F06]` it is a child component's next commit. Neither writer owns its own end state, and neither failure says anything: no log, no error, no rendered state. The predecessor brief called this the band-aid shape before the read found its second instance. **(verified, read out of the code)**

### The mechanisms that fail toward stale — the band-aids

**[F08] `visibleCanvasBand`'s refusal is right and its re-arm is missing** — `space-layer.ts:111` returns `null` for a box of no area or one wholly outside the window, and its own doc states the consequence: *"A caller that gets one writes nothing at all and leaves whatever cap it wrote last standing."* That is the correct instinct — a measurement taken in the dark reads zero and sticks. But `tug-sheet.tsx` re-measures on exactly three occasions, stated in its own comment at `tug-sheet.tsx:1451`: *"on open, on window resize, and once when the deck's settle ends."* A workspace becoming shown is none of the three, and `tug-sheet.tsx` does not import `useSpaceLayerShown` at all. So a window resized while the sheet's workspace is hidden refuses, and the stale cap — computed for a window size that no longer exists — stands for the life of the sheet. The refusal converted a mis-placement into a permanent staleness; it did not close the case. **(verified, read out of the code; the resulting mis-cap is inferred from the three-occasion list, not reproduced)**

**[F09] `useSpaceLayerShown` has two consumers, and neither is card content** — a grep across `tugdeck/src` finds it read in `tug-pane.tsx` (twice: the title bar's controls-width measurement at `:622`, and the pane's own geometry at `:2355`) and in `cards-card.tsx:1248` (a broadcast guard, not a measurement). `TugPane`'s use is the model — *"Nothing measures in the dark. [...] The effect is keyed on the shown bit, so the measurement is taken in the very commit that reveals the workspace"* — and it is exactly the arming that `[B03]` of the predecessor brief asked card content to adopt. Card content has not adopted it anywhere. **(verified, read out of the code)**

**[F10] `line-box-metric`'s never-on-geometry rule is correct for the loop it was written against and wrong for a hidden mount** — `line-box-metric.ts` re-measures only on a reconfigure or a `docChanged`, and its comment gives a sound reason: *"The publish below IS a geometry change [...] a metric that re-measured on geometry read a different shortest line at each height and drove the field between two sizes on alternating frames."* Re-arming it on `geometryChanged` would restore that oscillation and is not the fix. But a composer that first measures inside a hidden layer falls to `view.defaultLineHeight` and holds the estimate until the user types — the predecessor brief's `[F03]`, measured live at 14px against a healthy card's 30px. The metric needs a third occasion, not a relaxed second one. **(verified: the rule read out of the code; the stale value measured live in the predecessor brief)**

### The mechanisms that are sound — and why they are

**[F11] Six mechanisms in this area already fail toward visible, and each states its own failure direction in prose** — read cold, these are not churn candidates; they are the working precedent the defective ones never adopted:

- **`pane-occlusion-controller.ts`** — sole authority for one attribute, with the rule written out: *"When the test cannot prove coverage it leaves the pane visible — the failure mode is a missed hide, never a hidden exposed pane."* Reveals are synchronous; hides are lazy and blocked while anything animates. It reads `SHOWN_PANE_FRAMES`, so it never stamps a hidden workspace's panes.
- **The `arriving` hold** — `visibility: hidden` projected from a store field (`tug-pane.tsx:4706`), cleared by `_revealArrival`, and the reveal **carries a deadline**: `deck-manager.ts:2706` arms a `window.setTimeout(..., ARRIVAL_REVEAL_BOUND_MS)` that forces the decision if the quiet source never fires. This is `[L31]`'s *"Deferred work carries a deadline; when the deadline passes the work runs anyway"* implemented literally.
- **`drainArrivals`** (`deck-canvas.tsx:3163`) — the unconditional drain, called from five places *because*, in its own words, *"A mark is made in `addCard` and is meant to be cleared by the arrive beat ending. The beat is not guaranteed to run. [...] It is idempotent, so calling it from five places costs nothing and reasoning about which place owns a given arrival costs a defect."*
- **The settle's arrival opacity hold** (`deck-canvas.tsx:3989`) — the only other place in the codebase that writes `style.opacity = "0"` on a pane, and it pairs the write with an `inlineRestorer(frame, "opacity")` registered in `settleTweensRef` so that *"`arm`, the sweep and the unmount teardown all hand the opacity back — a frame left wearing the hold would be a card nobody can see."* It even handles the retarget case, preserving the *prior* restorer rather than capturing the hold as the value to restore.
- **`space-layer.css`** — one attribute, one rule, `display: none` chosen deliberately, and `[L06]` cited in the file: *"the state is an attribute the canvas writes and a rule here, never an inline style computed in React."*
- **The transcript's `data-replaying` gate** — derived from `useLifecycleState(...).state === "replaying"`, a published projection rather than a hand-written flag, which is `[L28]`'s shape; `visibility` not `display` so the inner list keeps measuring underneath.

**(verified, read out of the code)**

**[F12] The discipline the sound mechanisms share was learned at the deck layer and never crossed to the card layer** — every item in `[F11]` lives in `deck-canvas.tsx`, `deck-manager.ts`, `pane-occlusion-controller.ts`, `tug-pane.tsx` or `space-layer.css`. Every item in `[F05]`–`[F10]` lives in `session-card.tsx`, `card-host.tsx`, `tug-sheet.tsx` or `line-box-metric.ts`. The deck learned, incident by incident, that a beat may not run and a box may not exist; the card layer has been writing entrances and measurements as though mount were always visible. That is the fault line, and it explains the pattern the predecessor brief recorded as `[F08]`: the corrections that chase each other are all on one side of it. **(verified, from the file census above)**

### The tuglaws audit

**[F13] No law states the failure direction, which is why eleven mechanisms answered it eleven ways** — `[L06]` says appearance goes through CSS and DOM. `[L23]` says preserve user-visible state across teardown. `[L31]` says a refusal must be visible and deferred work must carry a deadline. `[L26]` says keep mount identity stable. Each of the defective mechanisms can be argued compliant with every one of them read individually: the fade *is* a DOM write (`[L06]`), opacity *is not* user data (`[L23]`), the fade *is not* a user gesture (`[L31]`), and the remount in `[F01]` *is* a genuine entity relocation where `[L26]` permits a rebuild. The laws are not wrong; they have a hole exactly where this class lives. **(verified, read against `tuglaws/tuglaws.md`)**

**[F14] Three smaller law findings, recorded so they are not re-derived** — (a) `session-card.tsx`'s fade registers no cleanup and says so, reasoning that *"if the body unmounts mid-fade, the WAAPI animation is garbage-collected with the detached element"*; `[L27]`'s *"Every acquisition returns its release"* admits no such exception and the comment is the kind `[L27]` explicitly calls a defect in itself. (b) `tug-popover.tsx:904` writes `contentEl.style.visibility = "hidden"` on a dismiss path and never clears it, which is safe only because Radix Presence unmounts the node — a `forceMount` content, which `tug-popover.tsx:45` contemplates, would reopen invisible. (c) `at0582` and `at0583` each name two different test files (`departure-ghost-*` and `workspace-*`), minted days apart by two arcs; the corpus has 30 such collisions overall, so this is pre-existing hygiene rather than a visibility finding, but these two are in exactly the area under audit. **(verified: (a) and (c) read out of the tree; (b) is a conditional that does not currently obtain)**

## Decisions {#decisions}

**[B01] The law to write is one sentence: a mechanism that decides visibility fails toward visible.** Every mechanism in `[F11]` already obeys it; every mechanism in `[F05]`–`[F10]` violates it; and no existing law states it (`[F13]`). It goes in `tuglaws/tuglaws.md` as a new law with three concrete clauses, each of which is a finding above rather than a generality:

- **One owner writes both states.** The party that writes the hide writes the reveal, on the same object, in code that runs whether or not anything else succeeded. A hide whose lift belongs to a second party — an animation's `commitStyles()`, a child's next commit — is the shape this law forbids. (`[F05]`, `[F06]`, `[F07]`)
- **A deferred reveal carries a deadline.** `[L31]` already says this for user gestures; this extends it to appearance, because a blank card is a refusal the user cannot read. `ARRIVAL_REVEAL_BOUND_MS` is the reference implementation. (`[F06]`, `[F11]`)
- **A refusal to measure re-arms; it never just returns.** Declining to measure in the dark is right. Declining and never asking again converts a mis-placement into a permanent staleness. The refusal registers the condition that will let it try again. (`[F08]`, `[F10]`)

**[B02] `[L23]` gains its third transition class: remount into a subtree with no boxes.** `[F01]`–`[F03]` establish it as real, declared, and unhandled. The law currently offers two mechanisms keyed to whether the DOM survives; this class is one where the DOM does *not* survive **and** the replacement has no layout. The rule for it: **a mount that may land hidden takes no measurement and plays no entrance — both are armed on the shown transition.** `useSpaceLayerShown()` is the existing arming signal and `TugPane` is the worked example (`[F09]`); card content adopts it. This makes `[B03]` of the predecessor brief precise about *why* rather than just *what*.

**[B03] The fade and the mask are rewritten to own their end state; the animator is untouched.** `SessionCardBody`'s fade gets an unconditional end-state write on both settlement and rejection — the shape `jots-card.tsx:529` already uses (`.finished.then(restore, restore)`, where `restore` clears the inline values the animator committed) — and it does not play at all when `useSpaceLayerShown()` is false, because there is no beat to share with a workspace nobody is looking at. `CardHost`'s mask gets a deadline: if `onContentReady` has not fired by it, the mask lifts anyway and the un-restored scroll position is the lesser harm. `tug-animator.ts`'s swallow stays exactly as it is — it is correct for the detached-element case it was written for, and `[F05]` is a caller defect, not an animator defect. This holds the predecessor brief's `[B04]` and its matching non-goal.

**[B04] The sheet clamp and the line-box metric each gain one occasion, not a relaxed rule.** `tug-sheet.tsx` adds the shown transition to its three re-measure occasions (`[F08]`) — the fourth occasion, keyed on `useSpaceLayerShown()`, leaving `[B07]`'s hold-still-through-motion argument intact. `line-box-metric.ts` adds the shown transition as a third trigger alongside reconfigure and `docChanged` (`[F10]`); it does **not** re-arm on `geometryChanged`, because the oscillation that rule was written against is real and re-introducing it would trade a stale metric for a flickering one.

**[B05] The reproduction lands before the fix and asserts state, not layout.** This carries the predecessor's `[B05]` forward with `[F01]` as the reason the harness missed it: a probe that moves a card between workspaces must assert the *inline* `opacity` on `.session-card` is not `"0"` and that `--tugx-editor-line-box` is the measured value, because the layout is correct in the failing case and a layout-only assertion is green on a blank card. `at0580` grows the same assertions on its existing legs. If the probe is still green with motion enabled, the next read is how `TugAnimator` behaves in the harness, not another probe.

**[B06] The sound mechanisms are out of scope for change and in scope for citation.** `[F11]` and `[F12]` are the audit's most useful output for the *next* arc: the deck layer has already paid for this lesson five times and written the reasoning down each time. The consolidation quotes those files rather than rewriting them, and `[B01]`'s law cites `ARRIVAL_REVEAL_BOUND_MS`, `drainArrivals` and `pane-occlusion-controller` by name so the next author finds a worked example instead of a principle.

**[B07] A lint is the only thing that keeps this from recurring, and it is cheap.** The census in `[F04]` was a fifteen-line script and it bounded the whole class. The same shape — a mount-once effect in `components/` that writes `style.opacity`/`style.visibility`/`style.display` or opens an animation, without an unconditional end-state write — is mechanically detectable and belongs beside the existing `audit-tokens` lints. Without it, `[B01]` is a paragraph in a document and the ninth mechanism gets added by someone who did not read it.

## Open Questions {#open-questions}

- **Whether `CardHost`'s mask has ever actually stranded a card, or is only shaped to.** `[F06]` is a code read, not a reproduction: the stranding needs a content factory whose `onRestore` does not cause a commit, and the read did not enumerate the factories. It matters for ordering, not for the decision — `[B03]`'s deadline is warranted by the shape alone under `[L31]` — but knowing the answer decides whether this is a fix or a hardening. The census of `onRestore` implementations settles it.
- **Whether `tug-list-view.tsx:3153`, `tug-list-view.tsx:3676` and `pdf-view.tsx:419` are in the class.** `[F04]` found them as mount-once measuring effects and did not judge them. They are inside card content and could mount hidden. Reading three effects settles it; it was left rather than guessed because a wrong verdict here would either add churn or leave a hole.
- **Why the harness did not reproduce `[F05]`** — carried forward unchanged from the predecessor brief's second open question. `[B05]` is written so the answer falls out of doing the work rather than preceding it.

## Non-goals {#non-goals}

- **Changing `tug-animator.ts`.** Its `commitStyles()` swallow is correct for the detached element it was written for, and its comment explains the unhandled-rejection reason the guard exists. Rejected by `[B03]`; also the predecessor brief's non-goal, and the read confirmed it rather than merely inheriting it.
- **Re-arming `line-box-metric` on `geometryChanged`.** The oscillation it was written to prevent is measured and real (`[F10]`). Rejected by `[B04]`.
- **Reworking the sheet's three re-measure occasions.** `[B07]` of `sheet-shade-placement` — hold still through the motion, re-clamp when the hand lets go — is sound and the read found nothing against it. `[B04]` adds a fourth occasion and touches none of the three.
- **Unmounting cards in hidden workspaces, or an eviction policy.** Both rejected by the predecessor brief (`[B06]`, and `[Q01]` of `workspaces-refine`); the read strengthens the case rather than weakening it, since `[F01]` shows the remount is the expensive event and keeping workspaces mounted is what avoids paying it twice.
- **Making cross-workspace moves preserve mount identity.** It would dissolve the class outright and it is the wrong trade here: the layer wrapper is what makes a hidden workspace cost a style recalculation instead of a rebuild, and portalling every pane out of its layer to keep identity would give that back. Recorded as considered and rejected so it is not re-proposed; `[B02]` handles the remount by declaring it instead.
- **The `at0582`/`at0583` filename collisions, and the 28 others.** Real (`[F14]c`) and not this work. A separate pass, or nothing.
- **The Workspaces card's press and mark.** Its own brief, `workspaces-press-and-mark-brief.md`, as before.

## Exit {#exit}

**An arc.** The read is done, so unlike its predecessor this brief's successor builds rather than investigates. Its shape, in the order the work must land:

1. **The reproduction** (`[B05]`) — red first, asserting inline `opacity` and the line-box metric across a cross-workspace move, plus the answer to why the earlier probes were green.
2. **The law** (`[B01]`, `[B02]`) — written into `tuglaws/tuglaws.md` before the code changes, because it is the thing each subsequent change is checked against, and because writing it second means writing it to match whatever got built.
3. **The two hacks** (`[B03]`) — the fade's own end state and its skip-when-hidden; the mask's deadline. These close the user's defect.
4. **The two band-aids** (`[B04]`) — the sheet's fourth occasion, the metric's third trigger. These close the class the defect belongs to.
5. **The lint** (`[B07]`) — last, because it needs the four fixes above to be green against it, and first in importance for anything after this arc.

Steps 1 and 2 before 3; 3 before 4 only because 3 is what the user is waiting on; 5 last. The three open questions are each settled by a read of a named handful of files and none of them blocks step 1.
