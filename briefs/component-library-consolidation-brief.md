# Audit, prune and consolidate the tugways component library

**Purpose:** The UI component library in `tugdeck/src/components/tugways/` has grown past what its authoring guide describes: it carries components nothing uses, repeats the same shapes in feature CSS, and has drifted in its prop vocabulary. The library should be a small, consistent, enforced surface again.

---

## Purpose {#purpose}

The request, 2026-11-11:

> I want to audit, consolidate, and generally improve the *UI component system* we use for Tug. Tasks I want done are:
> - List usage of all the components we have and call out the components that are not being used, listing them for possible elimination.
> - Find the component-like usages of UI elements that are not currently factored properly as re-usable components with established APIs.
> - For all components, I want to audit their APIs for consistency and correctness across the library.

The audit below was run the same day at `2a6eb3e10`. `components/tugways/` then held 368 top-level files, 106 of them `tug-*.tsx`, plus 278 files in `cards/`. The governing document is `tuglaws/component-authoring.md` ([L19]).

### API

**[F09] The prop vocabulary has drifted.** (agent read)

- Semantic colour: `role` in 11 components, `tone` in 6, and `tug-icon-button.tsx` line 53 maps `tone` onto `role`. Also `fillRole`, `confirmRole`, `iconRole`, `busyRole`, `onColorRole`, `iconColor`. `variant` means severity in the banners and layout in accordion, box, list row and tooltip.
- Size: six scales and three defaults. Most default to `md`; badge, icon button, slot, combo box, file chooser and filter field default to `sm`. The `sm|md|lg` union is declared ten times.
- Icon: a `ReactNode` in 11 components and a string name in 5 (alert, both banners, inline alert, sheet).
- Chain dispatch: `action` + `target` (button, cue), `dispatch: ActionEvent` (icon button), `senderId` form slots; in `tug-popup-list.tsx` line 346 `action` is a `ReactNode`.
- Smaller drift: `ariaLabel` in `tug-dialog-button.tsx` against `"aria-label"` elsewhere; `open` against `visible`; `subtitle` against `description`; five density vocabularies; four ways to override `data-slot`.

**[F10] Many components break the authoring guide's structural rules, including its named references.** A pattern-match pass over 117 files counted about 45 with no `forwardRef`, about 70 with no `...rest` on the root, about 75 with a closed props interface, 19 with a missing or mismatched `data-slot`, and 54 whose docstring does not cite [L19]; the counts are heuristic. The agent read confirmed the pattern and the specific cases: `tug-checkbox.tsx` and `tug-switch.tsx`, which the guide names as reference implementations, have closed interfaces and put `className` on a different element depending on whether a label is present; `tug-combo-box.tsx` and `tug-file-chooser.tsx` forward the ref to the input, not the root; `tug-copy-badge.tsx` puts the caller's `className` on a child; appearance is held in `useState` in `tug-label.tsx` line 219, `tug-textarea.tsx` line 213, `tug-combo-box.tsx` lines 227–228 and `tug-clamp.tsx` line 82. The best conformers are `tug-separator`, `tug-badge`, `tug-label`, `tug-input`, `tug-choice-group` and `tug-list-row`. (script count verified; cases by agent read)

**[F11] Callback props for user actions remain, against [L11], and near-twin components duplicate props.** Callbacks in primitives: `tug-toggle-button` (`onPressedChange`), `tug-dialog-button` (`onClick`), `tug-jump-to-bottom-button` (`onClick`), `tug-slot` (`onSelect`), `tug-slot-layout` (`onSelectSlot`), `tug-inline-dialog` (`onSelectOption`), `tug-placard` (`onClose`), `tug-find-bar` (`onClose`), `tug-combo-box` and `tug-file-chooser` (`onChange`, `onSubmit`, `onSettle`). Callbacks in feature components: `tug-changes-list.tsx` (nine), `tug-text-card-editor`, `tug-prompt-entry`. Near-twins: banner and pane banner; arc gauge and linear gauge; combo box and file chooser (about 18 shared props); sheet content and sheet panel (11 duplicated props); badge and copy badge (`TugBadge` already has `copyText`). (agent read)

(agent read)

**[F15] The authoring guide carries history its own rules forbid.** `tuglaws/component-authoring.md` is 1,627 lines and includes a retired experiment (the document-shrink-clamp section), "Phase E.3" and "A2.x" references, and commit hashes, while its docstring rule bans history and plan references. **(verified)**

## Decisions {#decisions}

**[B01] Delete everything with no consumer.** The six files of [F01] go, with their CSS, their tests, and the stale `tug-chart-glyph.css` section in `theme-pairings.ts`. Unused code in a library is read as endorsed, and each of these has a live replacement or no purpose.

**[B02] Delete the gallery-only components, except the textarea.** `tug-skeleton`, `tug-marquee`, `tug-split-pane`, `tug-markdown-view.tsx`, and the whole colour cluster (`tug-color-picker`, `tug-color-adjustment`, `tug-color-well`) go, with their gallery cards and registrations. The user's call on the colour cluster: the theme editor is probably never coming back. `tug-markdown-view.css` stays, because it is loaded globally and `tug-markdown-block.css` builds on it; renaming it to match its real owner is in scope. `tug-textarea` stays, because a multi-line field is a plausible need and the primitive is sound.

*Resolved during implementation, 2026-11-11:* deleting `tug-markdown-view.tsx` left its windowing engine — `lib/region-map.ts`, `lib/block-height-index.ts`, `lib/rendered-block-window.ts` — with no importer but their own unit tests; `lib/smart-scroll.ts` is shared with `TugListView` and stays. The plan's test non-goal kept tests of `region-map` and `block-height-index` on the assumption those modules lived on. They do not, so under [B01] the three modules go with their tests, as does the retired design they were the parts of. Five more tests (`fence-propagation`, `incremental-tail-update`, `incremental-tail-lex-integration`, `do-set-region-wiring`, `region-block-ranges`) ran local copies of the view's private algorithms and tested nothing that ships, so they go too. `parseMarkdownToSanitizedBlocks`'s `decodeBlocks`, `buildByteToCharMap` and `BlockMeta` lose their `export`, which existed only for the view. at0014 used to scroll by dispatching `tug-region-scroll-set`, which only the view handled; the fixture is a plain scroller, so the test now writes `scrollTop` directly and still asserts the same restore.

*Resolved during implementation, 2026-11-11 (the `internal/` reach):* [B05]'s act is that feature code stops importing `internal/tug-button`; the other `internal/` reaches stay allowlisted with a reason each. Walking the tree found four more than the fifteen counted at devising, so the internal-import allowlist holds nineteen reasoned infrastructure entries once the `tug-button` importers are fixed, not fifteen: `tug-text-editor/wave-caret.ts` and `overlay/overlay-surface-styles.ts` import `internal/` stylesheets (the overlay's list is the CSS closure of the placard's surface), and moving `tug-clamp` and `tug-context-menu` out of the primitive tier made their existing reaches count — the clamp measures with `internal/use-clamp-overflow`, shared with `internal/use-is-multiline`, and the PDF menu marks dismissals with `internal/synthetic-escape`. The placard, which reached `internal/tug-button` for its close button, moved onto `TugIconButton` (the same ghost icon button), so it adds no entry. `card-title-bar.tsx` and `log-inspector.tsx` also open `internal/tug-popup-menu`, so moving them off `internal/tug-button` leaves their entries standing with the popup-menu reason.

*Resolved during implementation, 2026-11-11 (one feature name):* [B05]'s renames drop the `Tug` prefix from a feature's exported symbols. `TugSessionIdentity` cannot become `SessionIdentity`: that is already the identity record type in `lib/session-identity.ts`, and the component's own file and several of its importers use both. The component is `SessionIdentityView` (props `SessionIdentityViewProps`, tier `SessionIdentityTier`), in `cards/session-identity.tsx` as planned; `TugSessionCitation` becomes `SessionCitation`. `QuitGuard` also names the store's class in `lib/quit-guard-store.ts`, but no file imports both, so the component takes the planned name. Moving `tug-session-identity` out of the primitive tier made its existing reach into `internal/tug-progress-pulsing-dot` count, so it joins `session-phase-dot.tsx` under the internal-import allowlist with the same reason. With the two popup-menu entries above, that is twenty-two reasoned entries in all, not the fifteen counted at devising.

*Resolved during implementation, 2026-11-11 (the role/tone renames):* [B03]/[B06]'s semantic-colour vocabulary is applied with five choices the decisions did not spell out. (1) A dialog's confirm role travels as `confirm={{ role }}` on `TugAlert`, `TugAlertSheet`, `TugConfirmPopover`, the `showAlert` options and the overlay alert request, so no prop or payload field ends in `Role`; `confirmLabel` stays beside it. (2) `TugArcGaugeSegmentTone` stays out of `TugTone`: its members are a categorical data palette (`input`, `cache-read`, …), not semantic colour, and folding them in would make every tone prop accept them. (3) `TugLabel`'s `iconColor` took any CSS colour; `iconTone` takes a named tone painted from the `tone-icon` token family, which is what every caller was spelling by hand (the gallery's four were the only callers). (4) The attribute follows the word: the progress indicator and gauges now write `data-tone`, the dialogs' icon `data-icon-tone`, and the banners `data-kind`; their CSS and the app-tests that read them moved with them. (5) `TugProgressIndicatorPhaseVisual`'s `role` field became `tone`, since it is the indicator's `tone` prop by another path.

*Resolved during implementation, 2026-11-11 (the rest of the vocabulary):* [B06]'s winners are applied with four choices the table did not spell out. (1) Density: `cozy`, `comfortable` and `detailed` each were their component's non-compact presentation and are now `regular`, but the gauges and the cue keep `compact` as their default rather than taking `regular`; flipping them would change every caller that relied on the default, which the size flip avoided by writing `size="sm"` out, and a density default is not drift. (2) Icons: the five components take `icon?: React.ReactNode`, sized to their slot by `internal/sized-icon.ts`. An alert raised through the overlay crosses the page bus, which carries data, so the relay sends the icon as its Lucide display name and the overlay page draws it back; an icon that is not a named Lucide element crosses as none. (3) `TugLabelSize` runs `8xs` to `8xl`, a type scale rather than a control size, so it stays its own type and V01 leaves a union that reaches past `TugSize` alone. (4) V01 reads the top level of `…Props` interfaces, so `TugButtonConfirmation.ariaLabel`, an object field, stays as decided; no file needed a V01 allowlist entry.

**[B03] `role` names semantic colour on controls that carry emphasis; `tone` names it on passive status surfaces; every other spelling is removed.** Approved by the user. This rules out `fillRole`, `confirmRole`, `iconRole`, `busyRole`, `onColorRole` and `iconColor` as prop names, the `tone`-to-`role` translation inside `tug-icon-button.tsx`, and `variant` as a word for severity. One name everywhere was the alternative; two names were kept because the two families take different value sets and renaming all of one would touch more call sites for no gain in meaning.

**[B04] Callback props become chain actions in primitives only.** Approved by the user. The primitives listed in [F11] move to `useControlDispatch` or `useResponderForm` per [L11]. Feature components keep their callbacks for now; converting `tug-changes-list.tsx`'s nine is a redesign, not a rename.

*Resolution, found while writing the checker's callback rule:* the rule reads every primitive, and five carry callbacks that [F11] does not list — the two editor surfaces (`tug-text-editor`, `tug-message-editor`), the editor's context menu, and the internal button and popup menu. They keep their callbacks and their allowlist entries say why: the editors' submit and change are the editor redesign this decision leaves out, the same way it leaves out `tug-changes-list.tsx`, and the internal building blocks are wrapped by public primitives that already dispatch through the chain. So after the conversions the callback allowlist holds `tug-icon-button`'s direct-action `onClick` and these five.

*Resolution, settled while converting:* existing names are used wherever one already means the act. The jump-to-latest button dispatches `last-turn`, the command ⌃⇧⌘] already sends, so the Session card's handler answers it and the Overview card gains the same handler. The combo box and file chooser report through `set-value` with phase `change` for every value and `commit` for the resting one, and `submit` for Enter, which retires `onSettle` without a new name. The dialog button and the inline dialog's options dispatch `select-value`. Two names are new, both declared outside the command table as control-to-host currency: `close-find` for a find bar's dismissal, and `select-slot`, whose value is the slot index, which `select-value`'s string id does not fit. A slot keeps its press to itself (it stops the click), which is what the slot picker used the click event for. The find bar and the file chooser give hosts a hook, `useFindBarHost` and `useFileChooserHost`, returning a scope component that registers where it is rendered, so a host that is itself a responder stays on the control's chain.

**[B05] The library has three tiers, and the directory says which is which.** Primitives at the top level of `components/tugways/` import no store. Building blocks live in `internal/` and are imported only by primitives. Feature components live outside the top level, without the `tug-` prefix. The single-consumer components of [F03] move to `internal/` or beside their one consumer; the store-bound files of [F14] move out; feature code stops importing `internal/tug-button`. This is the guide's existing public/internal rule applied, plus one new line: a primitive that imports a store is a feature.

**[B06] One vocabulary, written down once and typed once.** Beyond [B03]: one size scale with a documented default, one density vocabulary, `icon` as a `ReactNode`, `open`/`onOpenChange` for presence, `"aria-label"` as the accessible-name prop, one chain-dispatch prop shape, one way to override `data-slot`. The unions live in a single shared types module and components import them. The vocabulary goes into `component-authoring.md` as a table. The specific winners are chosen in the arc from the usage counts in [F09], the most-used spelling winning unless it is ambiguous.

**[B07] Every primitive conforms to the guide, and a lint holds it there.** Conformance is fixed starting with `tug-checkbox.tsx` and `tug-switch.tsx`, because the guide points readers at them, then the worst cases of [F10], then the rest. A conformance check (exported props interface extending native props, `forwardRef` on a DOM root, `data-slot` matching the file name, `className` through `cn()`, `...rest` on the root, the [L19] citation) runs in `just lint` with a ratchet: an allowlist of today's violators that may only shrink.

*Resolution, found while moving [F10]'s appearance state:* in `tug-combo-box.tsx` the highlighted row and the list's anchor moved to refs written into the DOM, but `open` stays in `useState`. It is not appearance: it mounts the portaled list, sets `aria-expanded` and is reported through `onOpenChange`. The label's measured truncation now writes into a span React renders empty, so the measurement no longer erases the required-marker span beside the text.

*Resolution, found while conforming the rest of the library:* the check reads what it was written for, which is components with a DOM root. A `tug-*` file that exports no component named for it is a module (a context, a helper module, an imperative API with its provider, a family of parts with no part named for the file), and only its docblock rules apply to it. A component that renders no element of its own declares `@no-element` on its props, and the guide now says so; the sheet's root, the tooltip and the action tooltip carry it. A props union counts when one of the interfaces it names extends native props, as the accordion's does. The structural rules read code with the comments removed, because the combo box had passed C04 on a docblock that only named its `data-slot`, while its root carried none. Where a component has two shapes, the ref, `className` and `...rest` follow the element the component is for: the popup button's trigger in both shapes, and the copy badge's button root, not the badge inside it. The find cluster's slot is now `tug-find-cluster`, and the two app-tests that select it moved with it.

**[B08] Missing variants are added to the primitive, and the reach-in CSS is deleted in the same change.** `TugListView` and `TugListRow` go first ([F07]): a content-fit sizing, a rail presentation, a struck or dimmed row state, a title slot. Then `TugTranscriptEntry` density, `TugInlineAlert` accent, `TugBadge` bare numeric, `TugColumnBadge` tone, and a button minimum-width or icon-size prop. A variant that lands without removing the selectors it replaces has only added code.

*Resolved in implementation (list view and row).* The four landed as `TugListView` `sizing="fill" | "content"` and `presentation="default" | "rail"`, and `TugListRow` `state="struck" | "dimmed"` (`TugSizing`, `TugPresentation`, `TugRowState` in the vocabulary module). The **title slot** is `TugListRowTitle`, exported beside the row: the reach-ins it answers were rows with free-form `children` borrowing the row's `tug-list-row-title` class onto a `TugLabel` of their own and then restyling that class from feature CSS, so the slot gives them the row's title by component and each feature styles its own class on it (`cards-row-title`, `cards-header-title`, `cards-space-title`). The rail presentation carries the content height, the visible overflow and the always-on flush hairline; the edge-to-edge insets stay on each rail card's own class as the list's and row's padding tokens, because the Arcs list keeps the default insets the Cards and Jots lists zero. What the remaining `.tug-list-(view|row)` selectors in feature CSS express is not one of these four — token and inset tuning on one instance, a list's own flex sizing inside its parent, a composed primitive's own parts (`TugSessionRow`, `TugAlert`), and the Session card's transcript-scroller rules — and Step 15's later items or no variant at all answer them. The `list-surfaces` census reads the Cards and Jots lists; the Arcs list mounts only over a project with arcs, and its one rule moved into the rail presentation verbatim.

*Resolved in implementation (the rest).* `TugTranscriptEntry` `density="compact"` is the Overview's whole attribution line — the Session card's type, value for value, on the 2.2em gutter with a 2px gap, with the per-voice glyph corrections — and the Overview's hand-built pinned-header copy wears the same `data-density`; the Session card's identical type rules stay in `session-card.css` for now, as a repeated shape rather than a variant. `TugInlineAlert` `accent` is the usage-limit notice's louder look (tone-coloured leading bar, tinted icon centred at the one-line size, title and message close); the notice keeps only its placement margin. The tally's "bare numeric" badge is `TugBadge` `numeric` (tabular figures): a ghost badge already drops its padding, and its subtle ink moved to the tally's own wrapper, which a ghost `inherit` badge takes. `TugColumnBadge` `tone="action"` is the slot-chip palette with its pairing table. The button floor is `minWidth="action" | "compact-action"` on the shared button, used by the attachment preview's footer; the primitives whose action rows hold caller-supplied buttons (alert, inline alert, pane banner, sheet, inline dialog) keep their container rule, because a container cannot set a prop on a child it is handed, and the compaction occupant's Cancel keeps its rule beside the grid placement it shares. `.tug-tab:focus { outline: none }` is the tab bar's own default: the bar's keyboard mark is the cursor ring inside the tab, and a UA ring there is only ever the cropped sliver both sheets suppressed. The `[D12]` the Overview's comment cited is a plan-local tag with no live decision behind it.

**[B09] Repeated shapes are extracted where the copies are identical, and adopted where a primitive already exists.** Extract: the body-kind header strip, the settings group, the rail card shell with its toolbar and empty line, the sheet header and notice, the receipt header, one point-menu hook, one span-portal hook, and the small primitives of [F08]. Adopt: the existing primitives named in [F08], and `TugPushButton`/`TugIconButton` for the raw buttons of [F04]. The two repo notices become one component or a `TugStepRow` variant.

*Resolved during implementation, 2026-11-11 (the CSS shapes):* [B09]'s extractions move each shape's rules verbatim into one place and leave every feature class standing beside the shared one, so selectors, tests and per-copy overrides keep their names. Six choices the decision did not spell out. (1) The body-kind strip is not `BlockStrip`: that is the tool-call header's slot shell (name, detail and actions spans laid out by `block-header.css`), and the eight body-kind headers are free rows of their own children, so mounting them in it would change their DOM and layout. The twelve declarations are identical, so they became one class, `.tugx-block-strip`, in `styles/tugx-block.css` beside the tokens they read, and each header wears it. (2) The rail shell's root, content column and list wrap are classes (exported as constants from `cards/rail-card-shell.tsx`) rather than components, because each card's root already carries its own refs, focus handling and test ids; the toolbar and the empty line, which a card builds from nothing, are `RailCardToolbar` and `RailCardEmpty`. The Overview's empty line was the same rule a fourth time and takes `RailCardEmpty` too. (3) The sheet notice comes in two layouts: `placeholder` (the hooks and skills sheets' centred loading, empty and error states) and `line` (the usage and data-visualization sheets' one muted sentence). The two are different rules, and each pair was identical within itself. The memory sheet's header is the shared one with `align="baseline"`. (4) The repo notices are one `RepoNotice` with a `kind`, not a `TugStepRow` variant: a step row leads with a status dot and a notice has none. Both test ids are kept, and the non-repo copy joins the no-git copy in `repo-notice-copy.ts`. (5) The census family for the receipt headers and the repo notice is `landing-receipts` (`at0804`) rather than `receipts-and-notices`, whose file already spends its time budget on three other surfaces. It reads the no-git notice, whose plinth the non-repo kind shares. (6) Two census readings are narrower than the families named at devising. Every body kind except the JSON tree mounts embedded in the app, where its strip is not drawn, so `body-kind-strips` reads the gallery's standalone JSON tree. The data-visualization sheet draws no notice in its fixture, so `sheets` reads the usage sheet's notice, which is the same rule. `TugSettingsGroup` is a new primitive, so the conformance check's gallery rule applied to it at once, and it gained a section on the `TugBox` gallery card rather than an allowlist entry.

**[B10] Near-twins share a base.** Banner and pane banner, the two gauges, combo box and file chooser, sheet content and sheet panel each share their common props through one type and one implementation path. `TugCopyBadge` folds into `TugBadge`'s existing `copyText`.

**[B11] Every surviving primitive has a gallery card, and the guide is trimmed to rules.** The gallery gap of [F13] closes after the prune and the moves, so cards are written once against the final API. `component-authoring.md` loses its history ([F15]) and gains the vocabulary table of [B06] and the tier rule of [B05].

## Non-goals {#non-goals}

- **Converting feature components' callbacks to chain actions.** Deferred by [B04]; `tug-changes-list.tsx`, `tug-text-card-editor` and `tug-prompt-entry` keep theirs.
- **A single name for semantic colour.** Considered and rejected in [B03].
- **Keeping the colour picker cluster for a future theme editor.** Rejected in [B02]; themes are hand-authored CSS.
- **Visual redesign.** Extraction and variants reproduce today's appearance. A change a user can see is a defect in this work, not a result of it.
- **Rewriting component token contracts.** The guide's scope boundary stands: tokens and pairings change only where a merged or extracted component requires it.
- **Unit tests for every primitive.** Coverage is worth its own look; this work adds tests only for behaviour it changes.

## Exit {#exit}

An arc. The order matters because each stage shrinks or settles what the next one touches:

1. Prune: [B01] and [B02].
2. Draw the boundary: the moves of [B05].
3. Settle the vocabulary and write it into the guide and the shared types module: [B03], [B06].
4. Conform the primitives under the ratcheting lint, exemplars first, with the primitive-only [L11] conversion: [B07], [B04].
5. Add the missing variants and delete the reach-in CSS, list view and list row first: [B08].
6. Extract and adopt the repeated shapes, and merge the near-twins: [B09], [B10].
7. Close the gallery gap and trim the guide: [B11].

Stages 3 and 4 touch the most call sites. Stages 1, 2 and 7 are mechanical. Each stage is independently landable, so the arc may reasonably be cut into more than one.
