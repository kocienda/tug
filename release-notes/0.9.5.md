# Tug 0.9.5

Tug 0.9.5 fixes a duplicate launch of Tug.app so it hands off to the already-running copy instead of complaining, and cleans up several rough edges in commits, reports, and notifications.

## Launching Tug

- Opening a file, clicking a notification, or launching Tug again while a copy is already running now hands off to that running copy instead of showing "Another instance is already running." The running copy comes forward and its window is restored if it was minimized.

## Commits and the Changes list

- Committing with staged files outside what you're committing is now explained clearly, listing the staged paths, and offers an "Unstage and commit" button to resolve it in one step.
- Fixed a case where `⌃⌘M` (auto-message) did nothing after clicking in the Changes shade, until you clicked back into the composer.

## Reports

- Report panels (shown for test runs and similar multi-step operations) are more reliable: a finished run's results no longer get overwritten or erased by a later or parallel run, a run that didn't finish is now labeled incomplete rather than shown as a false pass, and a long failure message is capped with a "Full output" option to expand it.

## Sharing

- Shared charts and diffs now wait for them to fully render before the share is captured, so shared images and PDFs no longer show "Drawing chart" or "Computing diff" placeholders.
- Shared charts now carry over any open marks and their reports.

## Notifications

- Settings ▸ General now shows your macOS notification permission status, with a button to fix it (ask for permission, open System Settings, or send a test).
- The test notification now waits 5 seconds and only posts after you've switched away from Tug, so you can actually see it.
