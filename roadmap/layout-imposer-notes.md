OK. I have a number of improvements I want to think about when it comes to the Layout section in the Lens, the layout imposer algorithm we user to size and position cards on the deck. Here are the features I want to consider:

- *A*: Add multi-select support to the Cards section of the lens, whereby I could shift+click or command+click with the mouse or shift+arrow with the keyboard when the Cards list has the keyboard focus to select more than one card. Once such a selection has been made, then all the resizing and repositioning features will then apply to all the selected cards, e.g. ⌘1 to move to slot one in the layout imposition algorithm.
- *B*: I want a new command to move a selected card or set of cards to the left/right *relatively* in the layout imposition slots. I'm thinking of ⌥⇧⌘[ and ⌥⇧⌘] to do this operation. I think these keyboard shortcuts fit in with the @commands.md scheme layed out in @tuglaws.
- *C*: All layout changes should be animated smoothly *always*. It still feels like sometimes cards hop and flash, and I want to root out when and why this happens.
- *D*: I want to introduce a new scheme to the way that the Card Widths and the number of Cards chosen in the Layout section in the Lens actually works. Right now, the idea is to make the cards *fit* into the deck space between the left and right rails/deck-edges, overlapping them if the cards don't fit in the available space. This approach is good, and I want to keep it. However, I now want to add another approach, and let's call it *flow*. This approach would treat the space between the deck space between the left and right rails/deck-edges as the *visible bounds of a horizontally-scrolling space*, and would always work, when needed, to minimally slide the active card so it is fully visible in this bounds. Does this make sense? So, let's think about what it would mean to have this second *flow* layout approach to stand alongside the current layout *fit* approach.
- *E*: The vertical splits for the sidebar cards has proven itself to be quite pleasant and useful. I want to consider how we could expand this approach to encompass content cards as well. Somehow, we would need to revise and extend the layout slot algorithms and the user interface to display cards when split. We should also have a new set of keyboard shortcuts that change between stack/split for the currently selected card/layout-imposition-slot, as well as another set of keyboard commands to move/reposition cards when they are split, e.g. move the currently selected card up/down, move-to-top/move-to-bottom.
